# weizhCode Claude Code 风格轻量 TUI Spec

## 背景

weizhCode 当前已经具备可运行的终端 TUI、配置驱动的 Provider 选择、流式回复和当前进程内多轮对话能力。但现有界面更像满屏应用：消息区、输入区和弹窗都带有较重的边框与布局感，视觉上不够接近 Claude Code 这类轻量命令行助手。

本阶段目标是只改造终端界面样式和必要展示字段，让启动态、输入区、消息流和底栏更接近 Claude Code 的简洁体验。本阶段不改 Provider、API 协议、配置格式或对话行为。

## 目标

- 将 weizhCode 的 TUI 改成类似 Claude Code 的轻量命令行界面。
- 启动后展示小型 ASCII Logo、产品版本、当前模型和当前项目路径。
- 使用暗色背景、灰白文字，并用紫色或青色做少量点缀。
- 保留多轮对话消息流，但去掉大卡片式消息边框。
- 保留当前输入能力：视觉上是一条简洁输入框，内部支持多行输入。
- 保留当前对话行为、Provider 行为、配置行为和流式输出行为不变。

## 功能需求

- F1：启动 TUI 后，顶部左侧显示小型 ASCII Logo。
- F2：顶部右侧显示 `weizhCode` 名称和当前版本号。
- F3：顶部右侧显示当前模型名。
- F4：顶部右侧显示当前项目路径。
- F5：顶部信息下方显示状态行：`Connected to 0 MCP server(s), 0 tools registered`。
- F6：输入框上方保留简洁消息流，用于展示当前进程内多轮对话。
- F7：消息流不使用大卡片边框展示单条消息。
- F8：用户消息在消息流中使用类似 `>` 的纯文本提示符展示。
- F9：AI 回复在消息流中使用安静、缩进或淡色文本展示。
- F10：AI 回复继续在生成过程中实时追加到当前回复文本中。
- F11：输入区域视觉上呈现为一条简洁输入框，而不是占据较大空间的编辑器。
- F12：输入区域继续支持 `Enter` 发送消息。
- F13：输入区域继续支持 `Shift+Enter` 插入换行。
- F14：底栏左侧显示当前配置名。
- F15：底栏右侧显示当前模型名。
- F16：整体颜色采用暗色背景、灰白文字、紫色或青色点缀。
- F17：错误弹窗仍可正常显示错误标题、错误内容和确认按钮。
- F18：界面改造后，用户仍能通过 `/exit`、`/quit` 和常见终端快捷键退出。

## 非功能需求

- N1：本阶段只改 TUI 样式和必要展示字段，不改 Provider、API、配置解析、会话历史或流式协议逻辑。
- N2：新界面应在常见 Windows PowerShell 终端中可读、可输入、不卡布局。
- N3：顶部、消息流、输入框和底栏在常见终端宽度下不应互相遮挡。
- N4：界面应保持克制，不使用大面积高对比边框或满屏卡片。
- N5：颜色点缀应少量使用，避免影响正文可读性。
- N6：现有自动测试应继续通过，并补充能覆盖新布局关键元素的测试。
- N7：本阶段完成后，四份流程文档应归档到 `specs/claude-code-style-ui/`，避免覆盖后续阶段文档。

## 不做的事

- 不修改 YAML 配置格式。
- 不修改 Anthropic、OpenAI 或通义千问 Provider 行为。
- 不新增模型切换、配置切换或设置界面。
- 不新增 tool use、MCP、文件操作、代码编辑或 Shell 执行能力。
- 不新增系统提示词、长期记忆或会话持久化。
- 不重新设计错误处理流程，只保证现有错误弹窗在新风格下可读。
- 不实现真正的 MCP server 或 tools 状态统计，状态行固定显示 0。

## 验收标准

- AC1：运行 `uv run weizhcode` 后，界面顶部显示小型 ASCII Logo。
- AC2：顶部信息显示 `weizhCode` 和当前版本号。
- AC3：顶部信息显示当前配置对应的模型名。
- AC4：顶部信息显示当前项目路径。
- AC5：界面显示 `Connected to 0 MCP server(s), 0 tools registered` 状态行。
- AC6：界面底栏左侧显示当前配置名，右侧显示当前模型名。
- AC7：输入区域视觉上是简洁输入框，不再是大型编辑器区域。
- AC8：输入消息并按 `Enter` 后，用户消息以 `>` 风格出现在消息流中。
- AC9：AI 回复以简洁纯文本风格出现在消息流中，不带大卡片边框。
- AC10：AI 回复仍然按流式增量追加到同一条回复中。
- AC11：`Shift+Enter` 仍能在输入区域插入换行，提交后保留完整多行内容。
- AC12：连续两轮对话后，消息流能展示多轮历史。
- AC13：错误弹窗在新样式下能显示错误标题、错误内容和确认按钮。
- AC14：`/exit`、`/quit` 和常见终端快捷键退出仍可用。
- AC15：本阶段改造不改变 Provider 请求映射、配置解析和会话历史行为。
- AC16：自动测试通过，并包含新布局关键元素的覆盖。
- AC17：完成后四份流程文档被移动到 `specs/claude-code-style-ui/`。
