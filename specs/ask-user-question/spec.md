# 计划模式需求澄清 Spec

> 状态：四份精简文档已获用户统一批准，已实现并进入验收；真实终端待用户观察。
> 本阶段独立存放，不覆盖 Agent Loop 等旧阶段文档。

## 目标与默认交互

新增 AskUserQuestion，让 Agent 在计划模式发现需求或边界不明确时，暂停当前任务向用户提问，收到回答后继续调查和制定计划。明确需求不强制提问；模型自行决定何时调用，不承诺每次一定提问。计划最终仍等待 /do，不因回答问题而自动执行。

默认每次一题，支持 0～4 个单选项，也始终支持自由文本。一次可连续澄清多个问题，但逐题呈现，不新增复杂问卷界面。

## 需求

- F1：专用工具只在计划模式提供；普通模式不提供，强行调用也返回模式拒绝，不等待用户。现有六工具能力不退化。
- F2：问题说明要确认的需求、范围、约束或验收边界，避免重复询问上下文已明确的信息。回答后可继续读类工具、追问或输出计划。
- F3：界面在对话区显示问题和编号选项；输入序号选择，也可直接输入回答。空白不提交；无默认自动选择。
- F4：等待回答时暂停后续模型请求和工具执行，界面可响应、可编辑输入；人类等待不受普通工具 30 秒超时限制。
- F5：回答作为对应工具结果写回原对话，继续同一 Agent Loop，不新建用户任务，不重复执行之前工具。问题和答案留在滚动记录中，退出不持久化。
- F6：交互工具独立串行，不能和只读工具并发或被跨越重排；同一响应多个问题逐个等待。
- F7：Esc / 运行中 Ctrl+C 取消整个当前任务；退出应用也清理等待。取消后不会把迟到答案交给下一任务，重复提交至多接受一次，已确认答案不被取消抹去。
- F8：等待时普通输入作为回答；/plan、/do 不作为答案，也不启动任务，保留草稿并提示先回答或取消。/exit、/quit、Ctrl+D 仍退出应用。
- F9：三种现有协议都支持定义注入、调用解析和结果回灌。无交互消费方时及时返回结构化不可用错误，不无限挂起。
- N1：问题、选项、回答、错误与状态沿用已知密钥脱敏和安全纯文本显示；显示副本不修改原始选项关联。
- N2：问题最多 1000 字符，选项至多 4 个、每项 1～200 字符且互不重复；自由回答最多 4000 字符。非法输入有明确提示。
- N3：等待不额外增加模型迭代；原 25 请求上限、未知工具阈值、历史配对和现有进程清理继续有效。
- N4：不增依赖、不改 YAML、不新增权限审批、计划自动落盘、多选、多题表单或普通模式问答工具。

## 验收

| 标准 | 可观察行为 | 需求 |
|---|---|---|
| AC1 | 普通模式六工具；计划模式三读类加 AskUserQuestion；强行普通模式调用零等待 | F1 |
| AC2 | 不明确任务能提问，回答后计划明确体现用户确认的范围；明确任务不被硬性插入问题 | F2 |
| AC3 | 编号选择和自由回答均正确回灌；空白、超长、非法序号可重试，未提交不续跑 | F3、N2 |
| AC4 | 等待期间不继续请求/执行，超过注入短工具预算仍可回答；UI 保持响应 | F4 |
| AC5 | 同任务问→答→继续→最终计划，历史完整配对；计划后仍等待 /do | F5、N3 |
| AC6 | 读/提问/读及连续提问严格保序，无并发问卷、无重放 | F6 |
| AC7 | 等待中取消/退出和迟到/重复答案均安全；取消后新任务可再提问 | F7 |
| AC8 | 忙时 /plan、/do 保留草稿并提示；退出与取消按键语义不变 | F8 |
| AC9 | 三协议同组模拟流程通过；无交互消费者返回错误而非挂起 | F9 |
| AC10 | 脱敏、安全显示、输入上限、原六工具及 Loop 回归通过；真实终端/API 与模拟证据区分 | N1～N4 |
