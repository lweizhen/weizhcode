## 1. 背景与目标

weizhCode 已有三种后端协议的流式多轮对话、Agent Loop、计划模式、需求提问、分层权限及 MCP 工具。对话持续增长时，工具结果、工具调用参数及原生协议负载会反复进入模型请求；目前缺少会话级上下文预算与历史压缩。

本阶段采用两层策略：先将过大的工具结果归档并替换为稳定预览，再在累计上下文接近窗口时生成结构化摘要，保留近期原文并补充恢复信息。原有权限、脱敏、工具采集上限、取消与迭代停止规则继续有效。

目标：

- G1：降低长会话的上下文溢出概率，明确处理仍无法容纳的请求；不承诺近似估算能保证任意输入永不溢出。
- G2：已决定的工具结果预览保持稳定，避免无意义地改写后续请求前缀；不据此宣称服务端实际命中缓存。
- G3：近期用户消息保留原话；较早原话单独存盘，模型获得有界摘要和原文索引，需要时显式重读。
- G4：正常、手动与紧急压缩共用核心规则，任何失败或取消都不能静默丢失当前用户请求或破坏工具调用配对。
- G5：对话与压缩相互隔离，摘要本身不能执行工具、生成审批或改变权限模式。
- G6：以离线测试验证预算、状态、历史与实际出站请求；真实模型费用和真实终端观察单独登记。

## 2. 已确认范围与解释边界

用户已确认采用完整范围：两层压缩、九部分摘要、近期文件与工具列表恢复、手动命令、上下文过长后的紧急压缩及一次原请求重试、可配置窗口大小。

用户另已确认用户原话策略：近期原话直接保留，较早原话单独归档；模型上下文保留摘要和重读索引。归档是本地会话资料，不提供下次进程启动自动恢复对话的能力。

以下为适配现有系统的明确口径，属于本 Spec 待审批内容：

1. 不机械累加缓存字段：现有统计已把各协议的输入量归一化，估算不得再重复加缓存读写量。
2. 工具结果应在最终入模截断之前进入归档判断；工具自身已停止采集的部分无法恢复，不把截断后的内容冒称完整源文件或完整命令输出。
3. 最近文件快照来自已获准且实际成功的读取内容，不由上下文管理器绕开权限另读一次磁盘。
4. 归档对象使用应用生成的安全身份；远端工具调用编号、消息文字与路径参数不能直接决定写入位置。
5. 只有正式摘要可进入新历史；缺少有效正式摘要时不退回采用包含草稿的整个响应。
6. 不复制其他项目的 Agent 重建方式、协议角色限制或工具实现；保留 weizhCode 现有长期会话、原生负载和权限生命周期。

## 3. 计量与固定策略

### 3.1 两种计量不混用

- 归档阈值与预览头部按 UTF-8 字节数计量，不能把中文字符数当字节数。
- Token 增量按文本字符数除以 3.5 向上取整估算，不集成精确 tokenizer。该比例只是应用近似规则，不是对任一模型分词方式的承诺。
- 预算对象是下一次实际请求：包括有效历史、工具参数与结果、稳定指令、动态补充及工具定义等可影响请求大小的内容，不能只统计可见聊天正文。
- “近期消息条数”指有效历史中的消息记录数，不指 UI 气泡数或工具调用个数。

### 3.2 固定值

| 项目 | 本阶段规则 |
|---|---|
| 单个工具结果归档阈值 | 大于 50,000 字节 |
| 同一工具结果消息的聚合阈值 | 大于 200,000 字节 |
| 预览头部 | 最多 20 行，同时最多 2,048 字节，不截坏 UTF-8 |
| 摘要输出预留 | 20,000 Token |
| 自动压缩安全余量 | 13,000 Token |
| 手动摘要请求安全余量 | 3,000 Token |
| 自动触发 | 轻量处理后估算量达到或超过窗口 − 20,000 − 13,000 |
| 手动摘要输入预检 | 窗口 − 20,000 − 3,000；不是手动命令触发门槛 |
| 近期原文目标 | 从尾部累计，至少 10,000 估算 Token 且至少 5 条；两者都满足后才停止向前取 |
| 文件恢复上限 | 最近 5 个，每个至多 5,000 估算 Token |
| 自动摘要熔断 | 连续最终失败 3 次 |
| 摘要自身过长的重试 | 先最多 3 次逐次移走最旧 1 组，再逐次移走剩余最旧组的 20%，向上取整且至少 1 组 |
| 单次压缩请求总上限 | 最多 12 个摘要请求、总等待最多 120 秒，以先到者为准；取消可提前结束 |
| 紧急压缩后的原请求 | 最多重试 1 次，不重复执行已完成工具 |

所有路径的摘要输出都受当前后端可用输出限制与 20,000 Token 预留约束；预留不等于强制请求模型生成 20,000 Token。实际输出不足以形成有效正式摘要时按失败处理。

## 4. 功能需求

### F01：会话资料与归档生命周期

进程启动时确定一次本会话身份，并固定到权限系统确认的项目根。工具结果和用户原文归档位于项目内按会话隔离的专用资料区，首次实际需要时按需创建，不为了普通启动强制写盘。

不同会话和不同调用不得覆盖彼此。进程退出后保留资料供用户检查，不自动清理，不扫描或恢复其他会话。项目根不可确认或归档区不可安全访问时，不向项目外另找位置保存。

### F02：用户原话保留与有界索引

将要离开近期原文区的真实用户消息，必须先成功归档其安全原文，再允许以摘要与索引取代它在模型上下文中的原文位置。保持原有顺序、消息身份及必要的时间信息；除已知密钥脱敏外，不由模型改写归档正文。

正式摘要的“用户原始消息与索引”部分保留用户意图、约束及原话位置。索引须标明覆盖范围、归档位置和读取方式，规模有界；不能为了列出所有历史编号而使索引自身无限增长。完整索引可分段读取。

真实用户输入与应用生成的摘要、提醒、恢复消息必须区分，重复压缩不得把旧摘要或系统补充重新当成用户原话归档。需求提问中的用户答案保留其已有来源，不伪装成新的权限批准。

用户原文归档失败或已存在记录内容不一致时，保留当前仍在内存的相应原文，不提交会移除这些原话的重型压缩。以前已离开历史的归档资料若丢失，应如实提示无法取回，不能从摘要伪造原话。

### F03：单结果与聚合的轻量预防

每次正常任务请求模型前，先检查有效历史中的工具结果；不调用 LLM。

对尚未决定的结果，先将超过单条阈值的项归档；这些项从剩余原文聚合预算中移除。若同一工具结果消息的剩余原文总量仍超阈值，按体量从大到小继续归档，直至达标。体量相同时按原始顺序处理。

所有超过单条阈值的项都必须独立处理，不能因聚合已经达标而略过。聚合测试须使用每项均不超过单条阈值的样本，避免混淆两条规则。

用户消息与助手正文不进入这一层工具结果替换；较早用户消息只按 F02 的归档和重型摘要规则处理。

### F04：归档与既有结果上限衔接

轻量处理必须能看到结果生产阶段可安全获取、经脱敏的文本，不能等到最终回灌截断之后才声称保存了完整输出。成功归档后，模型历史及后续实际请求使用预览，不通过原生协议附带字段再携带一份完整大结果。

归档正文完整性相对于工具本次实际采集到的内容；不取消原有读取行数、搜索命中数、命令输出采集、MCP 传输、超时或非文本限制，也不为补齐归档重新执行命令、远端工具或读取整个文件。

工具已声明截断时，归档、预览和摘要继续保留这一事实。UI 摘要与单项最终模型结果继续有界，成功/失败状态、调用配对及必要退出码等事实不得被省略标记覆盖。

### F05：稳定预览、唯一身份与失败重试

预览包含原始采集体量、受限头部、归档位置与明确重读提示；脱敏导致字节数变化时区分采集体量与实际归档体量，不谎称逐字节保存了秘密原文。

以本会话内实际调用的唯一身份识别结果，不仅依赖可能重复或恶意构造的供应商调用编号。已完成“保留原文”或“归档替换”的决定，在会话内不翻转；预览后续重用时逐字节一致，不插入新的时间戳或随机文字。

只有安全文件完整提交后才能公布引用并冻结替换决定。同一身份重复处理不得重复覆盖文件；不同内容冒用同一身份视为冲突。落盘失败保持原文、不冻结失败决定，下次可重试；其他正常结果仍独立处理。

已冻结保留的项仍属于实际出站预算，不得通过从统计中忽略它们伪称达标；必要时交由重型压缩处理。

### F06：会话级 Token 估算

锚定最近一次可用的主对话请求真实用量，并只估算其后新增或改变的请求内容；新用量覆盖旧锚点而非累加。对已经归一化的输入量，不重复加缓存读写量。

锚点必须与对应请求快照及已纳入的助手回复范围绑定，不能仅凭当前消息条数推断覆盖范围。历史归档替换、重型重建、指令或工具集变化后，失效锚点必须重置或安全校正。

首轮、用量缺失/异常、取消、流错误等无法可靠锚定时使用明确的近似降级；未知不当作真实零。主对话与摘要用量分别标识，摘要不能覆盖主对话锚点。

### F07：自动重型压缩与压缩有效性

正常请求顺序固定为：轻量预防 → 基于处理后的实际内容重新估算 → 检查阈值和熔断 → 必要时摘要 → 检查最终请求可容纳性。

摘要可以参照本轮完整有效历史以理解当前工作，但只用摘要替代较早部分，近期原文按 F10 保留。重建内容必须包含正式摘要、恢复信息及近期原文。自动压缩不能在同一请求前无进展地无限重复。

自动摘要有效的条件包括格式有效、必要用户原文已归档、调用配对完整、估算确有缩小且可供后续安全请求使用；不满足则不能把旧历史替换成“已压缩成功”的结果。

### F08：摘要独立请求与草稿隔离

使用当前选定的同一模型后端生成摘要，不自动切换服务或模型。摘要请求不携带工具定义，并明确禁止调用任何工具；即使模型意外返回工具调用，也不得交给执行器或审批系统，按无效摘要处理。

摘要提示要求先整理简短工作草稿，再输出正式摘要，二者明确分界。草稿不作为向用户展示的推理过程，不进入会话历史、归档、工具结果或普通日志；只有符合要求的正式摘要可继续使用。

正式摘要缺失、为空、分界不完整、输出被截断或必要结构缺失时失败；不能把整个响应作为兜底摘要，否则可能泄漏草稿或混入无效内容。

### F09：正式摘要的九部分

正式摘要按固定顺序包含：

1. 主要请求和意图。
2. 关键技术概念。
3. 文件和代码片段。
4. 错误和修复。
5. 问题解决过程。
6. 用户原始消息与原文索引。
7. 待办任务。
8. 当前工作，包括停在哪一步、未确认事项与已完成动作；这是最详细部分。
9. 可能的下一步。

无信息的部分明确标无，不编造结论。区分完成、失败、取消、未验证和仅提出的计划；不能把模型建议写成用户批准，也不能把错误或截断推断为工具成功。

再次压缩时整合上一份摘要与后续新增事实，仍保留原始用户资料索引，不层层嵌套整份旧摘要。

### F10：近期原文与协议完整性

从原有效历史尾部向前累计，达到 10,000 估算 Token 且至少 5 条消息后才停止；总历史不足时保留现有全部消息，不虚构记录满足下界。

截断边界不能分开助手工具调用及对应结果，不留下孤立结果、缺失调用或错误的 ID 配对。必要时向前扩大保留范围，不静默删掉结果修补配对。

保留消息的原生协议事实、正文与执行状态；除已经合法生效的轻量预览替换外，不重写近期用户原话或凭空加入虚构助手答复来伪装衔接。各后端请求仍必须合法。

如果近期原文自身过大，不能在不告知用户的情况下突破保留规则；最终放不下时受控停止并保留现有历史。

### F11：成功读取文件的恢复快照

跟踪本会话已获准且实际成功读取的本地文本内容，以及对应真实路径、读取范围、读取时间与截断事实。重复读取更新该文件最近记录，恢复时按最近读取顺序选最多 5 个。

使用读取发生时已经获得的纯净文本，不带显示用行号前缀，不额外绕过权限重读磁盘，不把局部读取冒称整个文件。远端 MCP 返回含路径的文字不自动视为已验证的本地文件快照。

每文件恢复片段最多 5,000 估算 Token，保留头部并明确截断。快照须标明是历史读取时内容，不保证与当前磁盘一致；涉及编辑仍须按现有规则读取和批准。

### F12：工具恢复与边界消息

恢复段包含近期文件快照、当前可用工具说明和边界消息。工具说明来自即将执行的正常请求的同一模式工具快照，名称、数量、参数约束一致；不能因为摘要保留过旧工具，就重新启用当前隐藏或不可用工具。

边界消息明确：需要代码或文件细节请重新读取，需要较早用户原话或结果细节请按归档索引读取；不要依据摘要或预览脑补代码、错误原文与授权。

恢复信息属于应用上下文数据，不代表新的用户命令、工具结果或权限批准。模式变化后，不得让旧恢复段冒称最新工具清单；权限判定继续以当前真实状态为准。

### F13：重建总预算与原子提交

提交重型压缩前，对正式摘要、恢复段、近期原文及实际请求固定开销一起检查。文件快照数量/片段和工具说明可在规定上限内进一步精简，不能靠反复添加恢复信息把上下文重新撑满；工具定义的真实参数约束不可静默删改。

近期原文保留规则与工具配对不能为“压缩成功”而暗中放宽。即使恢复段已精简，最终仍无法容纳时失败并保留旧历史，不空发、不循环重复摘要。

摘要候选重试时的移除只发生在临时输入中。只有必要归档、安全检查、结构检查和最终预算检查都成功，且会话仍未取消/变更时，才一次性提交新历史并重置估算基准。

### F14：手动命令与互斥

新增 `/compact`：空闲时无论是否达到自动阈值、自动熔断是否打开，均可发起一次核心摘要流程；空会话友好提示无内容，不收费空发。手动动作本身不额外执行轻量归档，但既有预览仍有效，必要的用户原文归档仍需成功。

手动 3,000 Token 余量仅用于摘要请求输入预检，不是允许执行命令的大小门槛。非空短会话也可发起摘要；结果没有缩小时如实提示，不能显示不存在的节省。无有效缩小或超预算时保留旧历史。

主任务、工具审批、需求提问或其他压缩正在进行时，不排队偷跑手动压缩；保留草稿并提示先完成或取消当前操作。压缩期间禁止启动第二个任务或切换权限模式。

### F15：斜杠命令与原有交互兼容

空闲输入的斜杠命令走统一命令路径；保留 `/exit`、`/quit`、`/plan`、`/do` 的既有语义，新增 `/compact`。未知斜杠命令给出可用命令提示，不发送给模型。

命令文字与压缩状态提示不作为新的用户对话写入历史。`/do` 仍可按原规则产生应用执行指令，但不冒称用户新写了一段原话。

需求提问或审批等待期间，优先遵守现有交互通道和取消规则，不能把答案误当压缩命令，不能把压缩或回答问题当执行批准。

### F16：请求上下文过长的紧急恢复

仅当当前正常模型请求被明确识别为上下文长度错误时，先确保轻量预防已生效，再绕过自动阈值与熔断执行紧急摘要。认证、额度、限流、普通网络错误或其他服务错误不能被错误识别为上下文过长。

紧急成功后基于新历史重新估算，并计入原请求输出预留及至少 3,000 Token 安全余量；确认可容纳才重试刚才的正常请求一次。重试仍过长或其他失败时，按正常错误结束，不再二次紧急压缩。

重试不重新追加用户消息，不重放已完成工具，不增加新权限，不重置 Agent 原迭代上限。失败流中的未确认工具调用不能执行或当作完整助手回合提交；UI 如已显示部分内容须明确该次未完成。

### F17：摘要请求自身过长的有界退让

自动、手动、紧急三条路径共用摘要输入过长处理。候选历史按完整用户任务及其助手/工具往返分组，首次已知过长后逐次移走最旧完整组：先最多 3 次每次 1 组，再每次移走剩余组数的 20%，向上取整且至少 1 组。

输入预检已超预算时可先退让，不发送已知放不下的请求。候选必须持续缩小，同时受 12 个摘要请求和 120 秒总预算限制。非长度错误不按该机制重试；没有剩余可用输入则停止，不发空摘要请求。若只剩不能继续移除的当前请求及受保护近期部分，仍放不下则停止，而非将它们删除以换取请求成功。

移除不是删除原会话资料。较早用户原话须已有归档，丢出候选输入的历史范围与由此产生的摘要信息缺口必须标明；保留当前请求及恢复所需近期原文，不静默假称摘要覆盖了未送给模型的内容。

### F18：自动熔断与失败分类

一次自动摘要流程最终失败，含所有内部长度退让尝试用光，计一次失败，而非每个子请求计一次。自动成功清零连续计数；连续 3 次失败后，本进程后续停止自动重型摘要，轻量预防仍运行。

手动与紧急流程绕过自动熔断，但不读写其连续失败次数，不因强制成功暗中解除已经熔断的自动状态。取消不计失败，也不伪装成功重置计数。

自动摘要失败若当前正常请求仍可安全容纳，可以提示后继续；否则受控停止或按已明确的长度错误走一次紧急恢复，不能为凑够三次失败继续发送已知过大的请求。

### F19：状态、用量与可见反馈

重型流程开始前显示自动/手动/紧急原因和进行中状态，结束显示成功、无缩小、失败、取消或熔断，包含压缩前后估算量与归档结果数量。失败不能编造压缩后为零或负的节省量。

统计区分主对话和摘要请求；摘要的已报告费用相关用量也纳入会话累计，子请求按自身身份只结算一次。失败/取消的部分用量保留“不完整”事实，不把摘要计入普通任务迭代次数，也不覆盖主对话估算锚点。

UI 不展示摘要工作草稿，不逐字刷出内部摘要；旧 scrollback 和已完成工具事实不因模型历史替换而消失。说明自动摘要会额外调用当前模型、可能收费，不承诺固定节省。

### F20：窗口配置与旧配置兼容

每个供应商增加可选 `context_window`，单位 Token；缺省或 0 使用应用默认：anthropic 为 200,000，openai 与 qwen 为 128,000。它们是可覆盖的应用估算默认值，不代表指定模型或兼容端点实际支持该窗口。

显式非零值必须是大于 33,000 的整数；负数、布尔、文本及不够预留预算的值在启动时清楚报配置错误，不启动一个每轮必然压缩的循环。原供应商六字段语义不变，旧配置仍可加载，配置修改后重启。

其余阈值和重试预算使用本章固定值，不新增面向用户的多参数配置、运行中换模型或额外摘要供应商配置。

### F21：文件安全、权限与归档重读

内部归档写入是固定用途的会话维护，不借模型调用写文件或命令工具完成；PLAN 下也可维护自己的资料区，但不能由此写任意项目文件。

归档区和临时位置必须校验真实根及重定向，不接受绝对路径、目录穿越、Windows 特殊路径或恶意 ID 控制目标；不得覆盖现有项目文件、凭据或他人会话。文件完整提交前不公布可用路径；根变化或取消后的迟到提交不得替换当前历史。

模型重读归档仍经既有读工具与当前权限检查，不能为重读关闭沙箱、跳过 deny 或私自通过命令读取。大记录应能分段定位，不因单行过长而永久无法获取细节。

归档和摘要只是数据，不能自授信任、批准工具或绕过当前模式。用户删除/修改资料后，如无法确认对应原文则明确报告不可用，不按同名路径内容假称它仍是原始记录。

## 5. 非功能需求

- N1：性能与响应。轻量处理不调用模型；磁盘、慢摘要及取消清理不能冻结界面。重复处理已决定结果不重复写盘；规模越界必须有界失败，不在主界面线程无限处理。
- N2：状态安全。归档账本、用户索引、文件快照、估算锚点和熔断计数跨任务保持一致；不能因每次用户提交重建状态而遗忘已有决定。所有对话改写与任务/压缩互斥，不暴露半更新历史。
- N3：取消与退出。Esc/Ctrl+C 可取消当前压缩；退出按原生命周期收尾。不再发后续摘要/普通请求，不把迟到结果覆盖新历史。已成功保存的资料可保留，不谎称取消会撤销磁盘提交或服务计费。
- N4：安全与隐私。已知密钥在预览、资料、摘要、UI 和日志中脱敏；除安全脱敏外保留原话。资料可能含项目代码、命令结果和用户文本，本章不承诺加密或识别所有未知秘密。资料目录加入忽略规则，不自动提交、上传或同步。
- N5：兼容。三协议、extended thinking、原生工具配对、MCP 稳定目录、权限层序、计划模式、需求提问、缓存用量和既有 Agent 停止条件保持。摘要不能改变工具执行顺序或重放业务副作用。
- N6：事务与故障隔离。轻量归档失败保持对应原文；重型失败或取消保留可用旧历史，已经独立完成的轻量处理可保留。磁盘满、坏记录、缺失用量及错误流不产生未捕获崩溃。
- N7：可测试。估算、归档、决策冻结、分组、近期边界和摘要解析可在无网络、临时资料目录下验证；界面自动测试、原生 Windows/POSIX 与真实终端/模型分开登记。
- N8：可观测。记录触发原因、请求次数、耗时、前后估算、是否降级/熔断与结果，但不记录完整草稿、密钥、完整敏感正文或原始异常响应；用量未知和资料缺失不伪装为成功。

## 6. 不做的事

- 精确 tokenizer、模型窗口在线探测、容量数据库自动更新或任意输入绝不溢出的保证。
- 摘要质量机器学习、自动评分、A/B 实验或自动切换其他模型修复摘要。
- 跨进程恢复会话、长期记忆、项目指令加载、Skill 恢复、多 Agent 并发会话与自动清理资料。
- 自动补采工具已经截掉的输出、重新执行命令找回内容、自动联网获取外部资料或恢复 MCP 资源。
- 取消原有工具采集/传输限制、权限系统重写、审批结果持久化到摘要或为归档重读开后门。
- 运行中修改全部阈值、提供单独摘要后端配置、无限摘要重试或把非长度错误一律当窗口错误处理。
- 资料加密、云同步、完整操作系统隔离或对已有同用户任意代码执行的防御保证。
- 在文档/开发验收阶段连接用户生产模型、收费服务，或读取/改动真实配置和其他阶段资料。

## 7. 验收标准

所有用例先用合成文本、临时项目/资料区、fake 模型及本地协议替身；以下是未来验收要求，不是已执行结果。

- AC01（F01/N2）：同会话跨多个任务使用同一身份与状态；两次启动身份不同，首次需要时创建资料目录，退出不删；无归档需求时不为该功能强制写盘。
- AC02（F02/F09）：多次压缩后每条被移出的真实用户消息仍有原文或明确脱敏原文记录；顺序与索引正确，旧摘要/应用提醒不变成用户消息，无须每次请求重放所有旧用户原话。
- AC03（F02/F13/N6）：用户原文保存失败、冲突或丢失时，不提交会移除该原文的压缩；原用户请求仍可见，界面明确说明失败。
- AC04（F03/F04）：安全采集到 80,000 字节结果，最终入模截断前保存对应完整安全文本；实际下一次请求含有界预览和正确调用身份，不附带另一份原始大结果。已在工具采集时截断的样本仍标截断。
- AC05（F03）：同一消息的六条各 40,000 字节结果，总量 240,000，按稳定次序仅归档足以达标的项；另用三条各 80,000 的样本确认三条均因单条阈值处理，而非误报为只需归档一条。
- AC06（F05）：同结果重复处理文件不重写、预览字节不变；保留决定不翻转；磁盘失败不冻结，恢复后可重试；远端 ID 重复/同身份不同内容不会覆盖另一条记录。
- AC07（F05/F21）：预览含体量、头部、位置、重读提示；中文/长行场景同时不超过 20 行与 2,048 字节且 UTF-8 合法；恶意路径/ID和链接不导致项目外写入。
- AC08（F06）：连续三个正常请求用量分别更新锚点而不累加；三协议归一化后的输入与缓存不重复计数，锚点后增量只计算一次。
- AC09（F06/F07）：轻量替换降低当前请求估算后，原本将触发的重型流程可以取消；历史/工具/指令变化使旧锚点安全失效；缺失/异常/部分用量不当零处理。
- AC10（F07/F20）：窗口 100,000 时，轻量后估算 66,999 不触发自动摘要，67,000 触发；熔断或忙碌条件下行为明确，不产生假进行中事件或重复触发。
- AC11（F08）：捕获摘要请求确认无工具定义且禁止调用；模型意外返回工具调用也零执行、零审批；正式输出外的工作草稿不进入 UI、历史、资料或日志。
- AC12（F08/F09）：有效正式摘要包含九部分及用户原文索引，已有失败/截断/待确认事实保持；空摘要、缺少正式部分、被截断或结构不全时保留旧历史，不回退采用原始全响应。
- AC13（F10）：长短混合消息同时满足近期 10,000 Token 与 5 条下界，短历史保留全部；工具配对边界前推，不产生孤立结果，三协议实际请求合法且原生调用事实不丢失。
- AC14（F11）：成功读取 7 个文件后只恢复最近 5 个，单个至多 5,000 估算 Token、头部保留并标截断；不额外读磁盘、不重读未授权文件；局部读取与磁盘后续变化不被冒称完整最新原文。
- AC15（F12）：压缩后工具说明与实际下一请求的同模式工具快照逐项一致；PLAN 无 MCP 定义，边界消息要求重读，旧摘要中的工具不能获得调用权。
- AC16（F13）：正式摘要、文件恢复与近期历史合并后仍超预算时不伪报成功；允许精简的恢复资料先精简，近期规则不暗改，最终失败保持历史且不循环。
- AC17（F14/F15）：低于自动阈值的非空会话可用 `/compact` 发起摘要，自动熔断不阻止；3,000 余量只管摘要输入预检。空会话不发请求，无有效缩小不伪报节省。
- AC18（F14/F15/N3）：任务/审批/提问期间不排队压缩，草稿与原交互保留；空闲未知命令不进模型，`/exit`、`/quit`、`/plan`、`/do` 的原有含义及权限行为保持。
- AC19（F16）：正常请求明确长度错误后，先轻量再紧急摘要，成功且重新估算可容纳时原请求只重试一次；用户消息只追加一次，已完成工具不重放。
- AC20（F16）：重试再次长度错误、摘要失败或重建后仍过大时受控停止，无第二次紧急循环；401/403、额度、429、普通网络/服务错误不误触发该路径。
- AC21（F17）：摘要连续过长时，输入组数先逐次减 1，再按 20% 递减；不拆调用配对、不空发、不删除真实历史，归档索引与未纳入摘要的范围明确。
- AC22（F17/N3）：所有摘要路径最多 12 个请求且总等待不超过 120 秒预算；每次长度退让确实缩小输入，非长度错误不重试，取消后无新请求或迟到历史提交。
- AC23（F18）：自动最终失败计数为 1、2、3 后停止自动重型摘要，轻量仍运行；成功清零，取消不改计数；手动/紧急可运行但不修改自动计数，状态跨用户任务保持。
- AC24（F19）：三种流程在耗时请求前显示正确进行中提示，结束显示真实前后估算/归档数或失败原因；摘要用量独立标识、累计只结算一次，不占 Agent 普通迭代次数。
- AC25（F20）：旧配置、缺省/0、合法覆盖三种情况工作；三协议默认符合本 Spec；负数/布尔/文本及不大于 33,000 的显式非零值清楚报错，示例同步。
- AC26（F21/N4）：归档重读走真实文件权限，deny/围栏/PLAN 边界保持；项目根变化、同名内容变化、恶意重定向或删除资料不导致越界或假原文，长资料可分段读取。
- AC27（N1/N2/N6）：慢磁盘、磁盘满、冲突、慢摘要和并发任务请求下界面可响应；归档账本/历史/快照无半更新，自动和手动流程不同时改同一会话。
- AC28（N3/N4/N8）：Esc/Ctrl+C/退出期间资源有归属并结束；不暴露密钥/草稿，不谎称磁盘提交、已执行工具或服务计费已撤销，资料忽略规则生效。
- AC29（N5/N7）：现有聊天、工具、MCP、权限、提问、流式、缓存与用量测试保留；新增出站请求体、原生历史、取消和完整离线回归通过，平台跳过如实登记。
- AC30（G1/N7/N8）：长任务离线场景确实多次触发预防与重型处理并继续；不可恢复的超大近期输入受控停止。真实终端与真实模型若未运行分别保持待验，不能仅靠测试数量声称任意长会话永不溢出。
