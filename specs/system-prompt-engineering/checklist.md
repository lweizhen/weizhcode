## 1. 验证与记录约定

项目根为 `D:/STUDY/weizhcode-python/`。所有命令在该根执行，测试目标与文件清单以已批准 Task 为准。测试尚未实现时不得因命令已写在本文就勾选通过。

各项使用以下验证组；实际执行结果见第13节。列出命令不等于已经运行，未运行项不得标为通过：

| 组 | 命令/方式 | 证据范围 |
|---|---|---|
| G1 | `uv run pytest tests/test_prompting.py -v` | 模块、空槽、基线、提醒、环境渲染 |
| G2 | `uv run pytest tests/test_environment.py -v` | Git/环境采集、降级、限额、取消和原生清理 |
| G3 | `uv run pytest tests/test_prompt_protocols.py -v` | 生产请求构造的捕获、缓存策略、稳定字节、入口保护 |
| G4 | `uv run pytest tests/test_cache_usage.py tests/test_provider_events.py -v` | 用量值、可用性、累计/异常/汇总 |
| G5 | `uv run pytest tests/test_stream_collector.py tests/test_turn_runner.py tests/test_user_questions.py -v` | Loop、上下文、等待、取消、结算 |
| G6 | `uv run pytest tests/test_provider_tools.py tests/test_protocol_integration.py tests/test_redaction.py -v` | 三协议工具配对/原生回放、实际数据与脱敏 |
| G7 | `uv run pytest tests/test_tool_registry.py tests/test_file_tools.py tests/test_tui.py -v` | 工具保护、精确模式工具集、界面 |
| G8 | `uv run python tests/manual_prompt_smoke.py` | 默认离线演示；不是当前服务/账号的实测 |
| LIVE | 用户明确许可后使用手动入口的 `--live` 场景 | 当前实际服务与模型的 API/缓存/人工观察 |
| TERM | 用户在 PowerShell 运行 `uv run python -m weizhcode` | 真实终端启动、交互、退出与肉眼体验 |

每条有四种记录状态：通过、失败、缺条件、未运行。只有有证据的通过才勾选 `[x]`；其他保持 `[ ]` 并记录原因。失败修复后须重新验证，保留最新证据和必要失败说明。

证据格式统一为“条目 ID｜状态｜命令/操作｜实际结果与退出码｜平台/协议/模型｜限制或下一步”。用量记录使用脱敏后的结构化摘要，不保存认证头、配置原文、密钥或私密文件内容。平台不支持的检查须写明跳过原因，不能把替身测试当作原生进程已验证。
