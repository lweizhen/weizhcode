# weizhCode 系统提示工程化 Spec

> 状态：四份文档已获用户明确批准；实现与离线验证已完成，真实终端/API及人工观察待验。证据见本目录Checklist第13节。
> 流程：Spec → Plan → Task → Checklist，每份单独生成并批准。只有用户明确要求精简时才压缩流程。
> 参考：用户提供的四份“系统提示工程化”材料；其 MewCode、SDK、双协议及历史验证结论不直接作为本项目要求或证据。

## 背景

weizhCode 已具备三种协议的流式对话、Agent Loop、六个文件/命令/检索工具，以及仅限计划模式的 AskUserQuestion。计划模式可以先调查、澄清需求并产出计划，等待 /do 后执行；取消、历史配对、结果限额及安全显示已经建立。

当前全局指令仍集中在固定文本中，计划提醒每次请求拼接到系统提示尾部；没有明确的模块装配、环境快照与稳定/动态通道分离。已有用量解析涉及部分缓存计数，但未完整暴露缓存读写及字段可用性，也没有证明本阶段缓存策略实际命中。

本章重构的是“给 Agent 的指令”：组织稳定规则、传递当前环境、控制动态提醒，并以真实缓存用量和人工场景观察效果。目标是提高一致性与复用机会，不承诺模型百分之百遵守提示词，也不以“设置了缓存字段”冒充节省已经发生。

## 已确认的范围与默认值

- 保留 Python 3.11+、HTTPX/原始 SSE、六字段供应商配置及现有启动方式，不迁移 SDK。
- 同时覆盖 Anthropic Messages、OpenAI Responses、通义千问兼容 Chat Completions；保留已有兼容端点体验，尤其不把 OpenAI 改成 Chat Completions。
- 保留安装的七个工具：普通模式向模型提供原六个工具；计划模式提供三个读类工具与 AskUserQuestion，执行端门禁不变。
- 七个固定模块按下文顺序装配；自定义指令、已激活 Skill、长期记忆三个可选位置仅为空槽，不接入真实来源。
- 计划提醒以当前用户任务内的模型请求轮次计数：第 1、5、9……轮完整，其余轮次精简。每个新用户任务重新从第 1 轮开始。
- 缓存信息只进入用量数据与显式启用的调试/验证输出，不新增 TUI 状态栏显示。
- 本章只提供人工对比用的典型场景及记录方式，不建设自动化评测框架。

## 目标

1. 全局指令按职责和优先级组织，内容可局部扩展，装配结果确定。
2. 稳定系统规则与工具定义构成可复用前缀；环境、模式提醒及历史不改变本项目选择的稳定部分。
3. 系统规则和工具描述共同强化关键约定，保留现有工具安全行为。
4. 动态补充指令按轮次进入请求副本，不写入长期保留的会话历史，不成为新的用户任务。
5. 缓存写入、读取、缺失及异常信息可观察，真实命中与行为改善分别验证。

## 功能需求

### F1：模块化装配与优先级

每个提示模块有稳定标识、优先级和正文。按优先级从高到低排列，七个固定模块依次为：

| 顺序 | 模块 | 主要职责 |
|---|---|---|
| 1 | 身份 | 说明 weizhCode 是终端 Coding Agent、能力与职责 |
| 2 | 系统约束 | 用户任务边界、可信来源、密钥保护、真实报告与不虚构安全机制 |
| 3 | 任务模式 | 普通执行与计划调查的总体约定；不包含本轮可变模式值 |
| 4 | 动作执行 | 多轮推进、按结果调整、并发/串行原则、取消和停止不等于完成 |
| 5 | 工具使用 | 专用工具优先、读后再改、精确替换、截断和失败处理 |
| 6 | 语气风格 | 直接、克制、必要时解释，不奉承、不虚构进度 |
| 7 | 文本输出 | 结果先行、必要时使用 Markdown、清楚交代完成与未完成内容 |

模块间以一个空白行分隔，空内容跳过，不生成多余分隔空行。相同优先级保持既定注册顺序；不得依赖无序集合或临时运行状态决定顺序。新增一个模块时只需提供内容并挂载到相应位置，不重写装配主逻辑。

这是应用内的组织优先级，不是创造新的服务端消息角色，也不使后面的模块有权推翻更高层约束。

### F2：三个可选空槽

固定模块之后预留“自定义指令 → 已激活 Skill → 长期记忆”，本章均为空，装配时跳过。空槽不读取磁盘、环境变量、项目指令文件、Skill 文件或历史记忆，不产生额外模型请求。

逻辑呈现顺序为“七个固定模块 → 非空可选模块 → 独立环境信息段”；环境信息不成为稳定模块的正文。

### F3：独立、有限的环境快照

每个被接受的用户任务开始时，采集一次工作目录、操作系统/平台、本地当前日期、Git 状态摘要、应用版本及当前模型，作为本任务的环境快照。工作目录反映工具实际使用的工作根，而非无条件假定进程当前目录。

环境段明确是“本任务开始时的快照”，不声称工具执行后 Git 状态仍实时准确。新用户任务重新采集；同一任务内部不每轮重复运行 Git。

环境信息与稳定指令分开构造并分开传递，逻辑上接在稳定内容之后；具体系统内容块或补充消息的协议承载方式在 Plan 定义。它不是需要模型单独作答的用户提问。

Git 查询只读、最多等待 2 秒，输出采集和摘要有界；界面保持响应，任务取消和应用退出时有清理路径。非仓库、命令不可用、超时、权限错误或目录信息取不到时省略或标注“不可用”，不假装仓库干净，不中断正常对话。Git 摘要以状态/数量为主，不读取文件内容、差异正文或远端地址。

### F4：稳定内容与动态内容分离

稳定部分只含内置模块、空槽装配结果与当前工具集的定义；不混入日期、工作目录、Git 状态、当前请求轮次、用户问题、工具结果或完整/精简模式提醒。

在同一服务、模型、模式、工具集合和定义版本下，连续构造的稳定内容及工具定义在实际序列化后应逐字节一致。环境或历史变化不能改变这部分。模式无关的稳定系统模块在普通与计划模式下相同。

模式切换会改变工具集合，修改工具描述也会改变前缀；这些是合法缓存边界变化，不能要求切换 /plan、/do 后仍命中同一条缓存。不能为追求前缀一致而把禁止工具暴露给模型，或移除执行端门禁。

“动态内容不进入缓存”在本项目中指：不纳入主动选择的稳定缓存部分，不给历史额外设置缓存边界；不承诺控制服务端所有自动缓存行为或数据保留策略。

### F5：按服务能力使用缓存

对支持显式缓存标记的 Anthropic 服务，在稳定内容结束处设置可复用边界，使稳定系统规则及前置工具定义有机会复用；环境和运行时提醒保持在稳定边界之外。本章不新增历史增量缓存。

OpenAI Responses、千问及兼容端点保持稳定内容优先，并按所选模型/服务实际支持的缓存方式适配；不能把不同协议的字段相互套用，也不能假定所有 OpenAI 模型只靠相同前缀就能自动复用。

不支持特定缓存参数的端点不得被盲目发送不兼容字段。原有正常对话、工具调用和取消不能因为缓存优化退化；协议名相同不代表兼容端点的缓存能力相同。具体能力判定、参数及明确错误处理在 Plan 写清，不增加通用自动重试、静默更换服务或模型。

缓存期限与边界策略为内部默认，不增加 YAML 字段。缓存长度门槛、有效期、并发/路由及权限等条件影响真实命中；不为凑门槛填充无意义指令，不保证首轮一定创建缓存或次轮一定读取。

### F6：关键规则双重强化

在“工具使用”等系统模块和对应工具描述中一致表达：

- 读文件、找文件、搜内容优先使用 read_file、find_files、search_content，不用 run_command 拼凑替代已有专用能力。
- edit_file 前先读取目标相关内容，使用真实原文做唯一精确替换；读取行号不是文件内容，不能猜测修改成功。
- 如信息不足，继续调查；计划模式可用 AskUserQuestion 确认需求和边界。用户回答不是执行授权，最终计划仍等待 /do。
- 对截断、失败、未知结果、取消及迭代上限如实说明，不把中间一次回复当作自动完成。

这里只强化指令和描述，不新增“读记录令牌”、编辑前运行时追踪门禁、权限弹窗、路径白名单或工具审批。原有准备阶段、唯一匹配、目标变化及临时资源保护继续有效。

### F7：带来源的动态补充消息

提供以 <system-reminder> 标签包裹补充内容的形式。只有本应用生成并标记来源的补充上下文进入该通道；用户文字、工具结果、文件内容或环境字符串中出现同名标签，不会因此被应用识别为更高权限指令。

稳定系统规则说明其用途：作为任务执行的补充上下文，不要求模型单独回应或复述。每次请求按需生成补充内容，加入消息/动态上下文通道；不拼到稳定系统正文，也不另开一次用户任务或一次模型请求。

每次注入基于对话历史的独立副本，不能改变保存历史的内容、顺序、角色或原始协议回放载荷。不能拆开、插断工具调用和对应结果；不得伪造调用标识、用户回答或工具结果来容纳提醒。

标签只是提示约定，不会自动赋予系统权限，不承诺消除所有提示注入风险。高优先级系统约束、真实工具白名单、模式门禁及取消控制仍由既有机制保障。

### F8：计划提醒的频率和状态保持

将原先拼接到系统正文尾部的完整计划提醒移入 F7 通道：

| 当前任务内请求轮次 | 提醒 |
|---|---|
| 1、5、9、13、17、21、25 | 完整版 |
| 其他轮次 | 精简版 |
| 普通模式的任意轮次 | 不注入计划提醒 |

完整版包含只读调查、必要时提问、确认与假设的区别、产出计划并等待 /do；精简版保留只读及等待执行指令的核心约束。二者不能互相矛盾。

轮次是 Agent Loop 的模型请求次数，不是流片段、工具个数或用户回答次数。AskUserQuestion 等待用户期间不额外计轮；回答后触发的下一次模型请求正常计轮。每个新用户任务从第 1 轮重新开始；/plan 只切模式不发请求，/do 切正常执行并沿用现有执行指令。

计划模式仍只允许三种读类工具及 AskUserQuestion；不能把“只读”误写成禁止提问，不能开放写入、修改或命令。

### F9：缓存用量的真实、健壮解析

在现有输入/输出用量之外，对外提供缓存写入、缓存读取及各字段是否被服务实际提供的信息，能够按请求输出，也能在有需要时汇总。缓存统计走调试/验证输出，不改 TUI 状态栏。

必须区分：
- 明确返回的有效 0：服务报告本次该项为零。
- 有效正数：按服务含义记录对应读/写。
- 字段缺失、服务不报告或语义不支持：显示“未提供/不适用”，不能伪装为已确认零值。
- 类型错误、布尔伪整数、负值或同请求累计值异常：安全处理、保留已有可信计数并标记不完整，不抛未处理异常。

同请求的重复/累计报告只更新快照，最终最多结算一次。流失败或取消时保留已收到的真实统计，但不能宣称完整；兼容千问末包空候选列表等现有流式行为。

缓存读写是输入统计的相关计数，不可在已有输入总量上再重复相加。各协议的输入总量口径和缓存子项关系分别适配，不用同一公式机械处理所有后端。只有真实返回信息能够作为命中证据；不从延迟猜测命中或凭空计算费用。

### F10：缓存验证与人工定性对比

准备可人工运行的验证入口和典型场景，不自动发起付费请求。缓存验证至少记录服务/协议/模型、模式、稳定前缀是否一致、每请求读写计数与字段可用性、实际结果及未满足条件。

在具备凭证、权限、长度和有效期条件的服务上，以同一稳定前缀连续请求，查看是否有真实创建/读取；改变环境或当前问题时，验证应用选择的稳定部分未变。可以使用受控的非敏感验证样本，但不修改用户原配置、不以其他服务的成功代替该服务的成功。

人工对比至少覆盖：专用工具选择、编辑前先读、只读调查与需求澄清、计划后等待、环境感知、取消后继续、提醒不被当作新问题。比较旧版与新版表现时记录相同任务/模型及必要环境差异；能记录耗时和用量，但不把单次观察当成统计显著改善或必然省钱。

### F11：跨协议和现有能力兼容

三种协议共享相同模块内容、环境语义、提醒正文和轮次节奏，传输结构按各自协议合法表达，不要求请求 JSON 字面相同。

保留 HTTPX/SSE、流式双路收集、完整流执行门槛、并发保序、25 请求上限、连续未知工具阈值、取消/退出、历史配对、Token 去重、问答等待与复用。必要的 thinking/签名/加密等原生回放信息不显示、不改坏。

不因参考材料采用 SDK、两种后端或要求角色严格轮流，就迁移本工程或增加错误限制。历史是否合法以对应协议及调用/结果配对为准，而不是一条通用“相邻角色不得相同”的假设。

## 非功能需求

- N1：确定性与可扩展性。稳定装配及工具顺序可重复；新增模块或提醒种类只改其局部定义和挂载，不改全部 Provider 的业务规则。
- N2：响应性与资源收尾。环境采集有界、可降级、可取消，不冻结 TUI；不遗留采集子进程或后台等待，不额外轮询 Git。
- N3：安全与最小环境信息。环境段不包含 API key、认证头、配置原文、敏感环境变量、文件正文或 Git 差异。沿用已知密钥脱敏及控制字符/纯文本安全显示；不把路径、Git 文本或用户自写标签升级为指令权限。
- N4：历史与原始数据安全。动态副本不能反向污染 Conversation、工具参数、用户答案和必要协议载荷；多轮、取消、流错误后下一任务仍可继续。
- N5：统计诚实且不重复。未知与零分开，异常不覆盖可信值，缓存子项不重复加到输入总量，不保证每个兼容端点上报完整统计。
- N6：工程兼容。不新增 SDK、Ruff/mypy、评测依赖或配置字段；保留现有 Python 版本、启动和三协议。已有测试只迁移被本章明确替代的提示装配/请求形态断言，不删工具、进程、脱敏、预算等安全断言。
- N7：验证结论分层。自动测试、原生平台、无界面真实 API、真实终端和人工定性观察分别记录；缺条件、跳过、字段缺失及未命中不是通过，不以旧章节结果冒充本章。
- N8：缓存优化有边界。不保证固定折扣、首字延迟或全服务命中；不把稳定/动态分段误称为关闭服务端历史缓存或数据保留的隐私控制。

## 不做的事

- 项目指令文件加载、用户自定义提示文件、运行时热加载及外部模板系统。
- 真实 Skill 内容加载、自动 Skill 激活、真实 MCP 工具/资源接入。
- 自动记忆、长期记忆写入/检索、计划自动落盘、会话持久化。
- 历史压缩/裁剪、历史增量缓存边界、Token 预算停止。
- 新权限系统、逐次审批、执行沙箱、路径白名单、读前编辑的运行时硬门禁。
- TTL、缓存边界、提醒间隔、模块开关的用户配置化。
- TUI 缓存状态栏、费用估算器、强制切模型、为命中缓存无意义拉长生产提示。
- 自动化评估平台、自动评分、批量收费实验、生产行为必然改善的承诺。
- 新后端协议、SDK 迁移、工具集增删或本章之外的模型迁移。

## 验收标准

| 标准 | 预期行为与验证方向 | 覆盖 |
|---|---|---|
| AC1 | 七固定模块按规定顺序、空行分隔；同优先级保序；挂载新模块自动参与装配 | F1、N1 |
| AC2 | 三可选空槽被跳过，不留多余分隔、不读取真实来源；环境独立在后 | F2 |
| AC3 | 环境段能说明工作根、平台、本地日期、Git摘要、版本、模型，标明任务开始快照；新任务更新，同任务不重复采集 | F3 |
| AC4 | 非Git目录、缺Git、超时/权限/目录错误降级，界面可响应；取消/退出无遗留采集进程；输出有界 | F3、N2 |
| AC5 | 同服务/模型/工具集合下稳定序列化逐字节相等；改变环境、历史或提醒详略不改变稳定部分 | F4、N1 |
| AC6 | 模式无关稳定模块跨模式相等；normal六工具、plan三读类加AskUserQuestion；模式切换前缀变化被正确识别而非绕过门禁 | F4、F8、N8 |
