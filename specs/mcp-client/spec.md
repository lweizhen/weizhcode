## 1. 背景

weizhCode 已具备多协议流式对话、Agent Loop、六个内置工具、计划模式下的需求提问，以及分层权限规则和工具审批。当前工具身份、权限分类和执行入口仍主要围绕内置工具；界面中的 MCP 数量尚不代表真实外部连接。

本阶段引入只面向工具能力的 MCP 客户端：用户声明 Server，启动时建立连接并发现工具，把它们接入既有工具中心、权限审批、事件展示与结果回灌。Agent 和 LLM Provider 不需针对某个 Server 编写专用流程。

用户提供的四份参考文档只作为参考，不沿用其中的其他项目路径、历史验证结论或“权限模块零修改”等不适合当前代码的约束。上一阶段尚未完成的真实终端、真实模型和平台验收，也不因本阶段立项被追认为通过。

## 2. 目标

- 支持本地 stdio 和远程 Streamable HTTP 两种传输，由官方 Python MCP SDK 承载协议行为，不自研 JSON-RPC 协议栈。
- 配置驱动连接、发现与注册工具，完成初始化握手、列工具、按需调用的三步会话。
- 复用每个 Server 的已建立会话；多个 Server 相互隔离，单点失败不妨碍其他工具与纯聊天。
- 将远端工具接入已有统一工具接口、Agent Loop、三种 LLM 后端和工具行展示。
- 对项目配置的首次启动建立独立信任确认，且与工具调用权限分离。
- 默认对 MCP 工具调用进行审批；不因 Server 自报只读而自动信任，不在 Plan 模式开放 MCP 工具。
- 保留现有内置工具的黑名单、文件范围限制、规则、模式、审批、取消和历史一致性，不以支持扩展工具为由放宽未知工具检查。

## 3. 已确认的产品约束

### 3.1 配置约定

MCP 与模型供应商配置分开，使用独立 YAML：

- 用户级：`~/.weizhcode/mcp.yaml`。
- 项目级：`<项目根>/.weizhcode/mcp.yaml`。
- 顶层使用 `mcp_servers` map，key 是 Server 标识名。
- 按 Server 名合并，项目级同名定义整条覆盖用户级，不拼接字段；没有第三个 MCP 配置层。
- Server 显式声明 `type: stdio` 或 `type: http`。
- stdio 使用 `command`、可选 `args` 和 `env`；HTTP 使用 `url` 和可选 `headers`。
- 只在 `env`、`headers` 的值中展开 `${VAR}`，不展开 Server 名、command、args、url 或工具名。
- 引用的变量未定义时跳过该 Server，提示缺失变量名，不以空字符串继续连接。已定义但值为空与未定义区分处理。

示例只展示格式，不授权下载、启动或连接示例中的任何程序或地址：

```yaml
mcp_servers:
  local_demo:
    type: stdio
    command: python
    args: ["-m", "example_mcp_server"]
    env:
      DEMO_TOKEN: "${DEMO_TOKEN}"
  remote_demo:
    type: http
    url: "https://mcp.example.com/mcp"
    headers:
      Authorization: "Bearer ${REMOTE_MCP_TOKEN}"
```

模型供应商的六字段配置不因 MCP 扩展而改变。

### 3.2 两种独立授权

| 授权 | 决定什么 | 不代表什么 |
|---|---|---|
| Server 启动信任 | 是否允许启动本地 Server 程序，或连接项目配置声明的远程端点 | 不代表允许模型随意调用它的工具 |
| MCP 工具调用权限 | 是否允许当前调用，或按明确规则复用许可 | 不约束 Server 在启动时已经做的操作，也不证明 Server 实际只读 |

用户级配置视为用户主动信任；合并后来源为项目级的 Server，首次连接前必须确认信任。信任持久记住，只绑定当前项目与已确认的 Server 启动/连接配置；配置变化后重新确认。信任记录属于本地控制数据，不提交 Git，不存储凭据明文。

### 3.3 本章协议范围

按已确认的初始化握手式会话工作，由 SDK 完成适用协议版本的初始化、就绪通知及后续请求。SDK 与协议兼容范围在 Plan 明确并在测试中验证；不把参考中的接口名当成所有 SDK 版本通用接口，也不承诺覆盖未来或全部 MCP 版本。

Streamable HTTP 必须处理适用协议下的 JSON 响应和请求关联 SSE 响应。没有主动推送功能不等于拒绝接收调用响应中的 SSE；旧式独立 HTTP+SSE 传输不在本章范围。

## 4. 功能需求

### F1：两层配置加载与覆盖

缺失或空配置视为无 Server，正常启动。YAML 不可读、语法非法、重复键或顶层结构非法时，跳过该文件并给出脱敏告警，另一层仍可使用。合法 map 中的单个 Server 定义非法时，仅跳过该 Server。

覆盖先按名称决定来源，再校验最终定义：项目级已声明的同名 Server 即使定义非法或变量缺失，也不能悄悄回退启动用户级同名 Server。整份项目文件无法解析而被跳过时，仍可能使用有效用户层；告警需如实说明，不声称坏文件实现了禁用。

### F2：类型校验与环境变量展开

校验 Server 标识、传输类型和字段类型。stdio 的 command 必须是非空字符串，args 为字符串数组，env 为字符串 map；HTTP 的 url 必须是有效 HTTP/HTTPS 端点，headers 为字符串 map。缺字段、非法类型及不受支持的传输均不能被猜测成可执行配置。

对最终采用的配置展开环境变量，支持在一个值中嵌入多个引用；缺失任何变量都跳过该 Server。展开不改写原始文件，不在警告中输出展开后的值。不主动安装缺失的 Server、执行安装命令或将 command/args 拼成 shell 脚本。

### F3：项目级 Server 启动信任

任何项目级 Server 启动或首次联网前，展示其来源、Server 名、传输、本地命令与参数或远程端点的安全预览，以及启动阶段可能执行本地代码或发送凭据的说明，要求真实用户选择信任或跳过。不能用模型、文件、工具输出中的“已批准”文本替代选择。

拒绝、关闭确认或没有可用交互通道时，跳过相应 Server，不启动它，也不阻断其余可用 Server 与纯聊天。取消应用启动时结束整个启动流程并清理已拥有的资源，不能把取消当作信任。

允许记住的信任必须限定当前真实项目身份和相应 Server 的有效启动/连接定义，覆盖 command、args、显式 env、url、headers 等相关变化；名称相同不等于配置相同。敏感展开值的变化也不能静默沿用旧配置的信任。具体比较与安全存储方式由 Plan 定义；它不是对程序二进制、包版本或远程服务内容的完整性认证。

信任记录缺失、损坏、不可确认或保存失败时不得假称已永久信任。保存明确失败可仅为当前启动使用刚获得的明确选择，并警告重启仍需确认；结果不确定时不得擅自继续。信任只在启动阶段读取，本章不提供管理页面、热加载或自动信任功能。

### F4：两种传输与标准会话

stdio 以配置的程序和独立参数启动本地子进程，通过标准输入输出收发 MCP 消息；运行根使用当前项目根，显式 env 覆盖相应基础环境变量。stdio stdout 保持协议通道，Server stderr 不可未经处理直接污染终端或泄漏凭据。

Streamable HTTP 使用指定端点与配置请求头完成会话；支持适用协议需要的内容类型、版本/会话标识及认证头。不得把敏感请求头随跨来源重定向转发；认证失败是可诊断连接失败，不自动发起 OAuth 登录。

遵循 JSON-RPC 2.0，请求与响应按 id 异步配对，通知不冒充请求完成；乱序响应不串结果，连接错误不能使等待者无限挂起。初始化成功且 Server 提供工具能力后才进行工具发现，不在未完成会话时接纳工具调用。

### F5：启动发现、时间预算与失败隔离

在进入 TUI 前完成配置合并、必要的信任确认及工具发现。已获信任且有效的 Server 并发建立连接；单个 Server 的连接、初始化和完整列工具序列共用 30 秒启动预算，不为每一步重新计算 30 秒。用户做信任选择的时间不计入网络/进程连接预算，不能承诺包含人类等待的启动总时长为 30 秒。

跟随工具列表分页直到结束；重复或非法分页状态不能无限循环。没有工具能力或返回空列表时明确区分“连接成功但零个工具”与“启动失败”。连接、握手、列工具失败或超时只影响该 Server，并清理它已经创建的资源；其他 Server 和内置工具不被整体撤销。

进入 TUI 时工具快照确定。启动期间的进度与失败原因可见、脱敏且有界；无 MCP 配置时不增加 Server 信任提示或外部连接。

### F6：工具命名、注册与元信息适配

对外工具名为 `mcp__<server>__<tool>`，保留内部到来源 Server 和远端原名的映射。名称必须满足当前三种 LLM 后端共同的合法字符与长度限制；不以静默截断或替换名称制造冲突。

工具描述为空时提供可追溯来源的兜底说明；参数 Schema 在本地及当前 LLM 请求可支持的范围内保留原意，不悄悄删除约束以强行注册。非法名称、重复全名、非法或不受支持的 Schema 单独告警并跳过相应冲突/非法工具，不覆盖内置工具或其他已注册工具，不因此丢弃其他合法工具。

远端只读提示只作为非权威元信息，不自动转化成审批豁免、Plan 资格或安全并发资格。描述、Schema、Server instructions 与返回内容都是外部数据，不提升为系统级指令，不据此新增权限或信任。

### F7：MCP 调用权限与四档模式

只有成功接入并登记来源的 MCP 工具可进入外部执行通道。未知名称、未注册对象、非法参数或失败连接不能靠带有 `mcp__` 前缀绕过门禁。

MCP 继续使用会话 > 本地 > 项目 > 用户的既有权限层序和同层 deny 优先原则；增加对完整 MCP 工具名及 Server 工具组通配规则的支持，例如 `mcp__demo__echo`、`mcp__demo__*`。规则不得顺带匹配内置工具。允许与拒绝的效果、审批事件和结构化来源需可区分。

| 模式 | MCP 行为 |
|---|---|
| DEFAULT | 显式规则优先；未命中则审批，不因只读提示自动放行 |
| ACCEPT EDITS | 与 DEFAULT 一样，不能把外部调用当成内置文件编辑免审批 |
| PLAN | 不向模型提供 MCP 工具；执行端也硬拒，allow/BYPASS 规则不能改变当前 PLAN 限制 |
| BYPASS | 无命中 deny 时可按现有模式跳过单次审批；不能跳过启动信任、配置有效性、参数校验和已注册身份检查 |

MCP 审批沿用允许本次、允许本会话、永久允许、拒绝本次四种选择。此章的 MCP 规则与记住的授权以完整工具身份为单位，不宣称绑定本次参数、远端文件路径或调用内容；审批中必须明确提示会话/永久允许可涵盖该工具后续不同参数调用。自动保存仅生成精确工具名，不扩大为整个 Server 通配规则。

现有内置命令黑名单和文件范围限制继续作用于内置工具；不能根据 MCP 名称、参数中恰有 path/command 等字段就声称可约束 Server 的实际行为。新增可信登记和专用权限处理，不将所有未知工具默认放行。

### F8：调用、会话复用与结果适配

获准调用复用对应 Server 的现有会话，将正确的远端原名和经验证参数送入调用请求，不每次重新启动 Server。MCP 调用本章按保守的有副作用类别顺序调度，不因只读提示参加只读并发批；既有内置只读工具的有界并发与结果保序不退化。

每次远端调用使用 30 秒执行预算，审批等待不占用此预算。结果中的文本块按原序合并；远端工具错误保留可用文本并标为结构化错误，不丢失原调用 ID 或错配到另一轮。

非文本内容不送入模型或终端渲染，明确提示存在不支持的内容，不声称已处理图片、音频或资源。混合内容保留支持的文本并标注省略；仅有不支持内容时给出明确的不支持结果，而不是空白成功。结构化数据若需转换，仅作为有界文本数据，不扩展为资源解析或多模态能力。

### F9：错误、取消与连接失效

协议错误、远端报错、认证失败、超时和连接中断均给出脱敏、有界且可区分的结构化结果，供 Agent 调整策略；普通工具失败不直接终止 Loop。失败不误报成功，审批选择本身不冒充执行结果。

等待审批或执行时支持现有用户取消，停止本地等待并在适用协议和 SDK 能力内传达取消；补齐历史中每个调用的结果，后续对话仍可继续。取消、超时或断线不代表远端副作用回滚，不把“未确认完成”说成“从未执行”。

确认已失效的会话在本次运行保持不可用，后续调用及时返回不可用错误，不自动重连、重放调用或更换端点。一次工具业务报错不等于连接已失效。启动后的工具定义快照不因失效自动改变，也不因列表变化通知刷新。

### F10：生命周期与退出清理

对每个 Server 缓存且独立拥有连接、会话、请求等待者和本地子进程资源。正常退出、启动取消、初始化失败、运行异常及重复关闭均能收尾，不让失败 Server 的关闭阻断其他 Server 清理。

退出采用整体 5 秒正常关闭预算，必要时进入受控的本地强制终止/回收流程；不能只停止等待、留着自有后台任务继续运行或写入。HTTP 按所选协议与 SDK 关闭本地流/会话，远端支持适用会话终止机制时尽力通知释放，不保证所有 Server 接受相同的 DELETE 行为或立即停止远端工作。

不能在硬截止已到但进程仍存活时报告“全部清理成功”；无法确认清理或远端完成情况必须明确提示。具体平台能力、正常预算与强制回收的可验证界限在 Plan/Checklist 中落实。

### F11：界面、来源与可诊断性

启动显示连接/发现状态，进入 TUI 后显示真实成功连接的 Server 数量与注册工具数，不继续使用占位数值。工具发现为零、工具被跳过、Server 失效等状态不能混淆。

MCP 调用沿用现有工具行、审批、执行阶段与结果摘要，能辨认 Server 来源；过长内容截断并标注。菜单、错误和控制台日志不得接纳终端控制符或富文本注入；真实用户选择与模型文本严格区分。

Server 的原始 stderr、异常正文、url 中的认证部分、环境变量值和请求头不能绕过脱敏通道直接打印。告警可提供错误类别与 Server 标识，不依赖回显秘密才能诊断。

### F12：既有能力保持

无 MCP 配置时保持原来的对话和工具行为。Anthropic、OpenAI、通义千问三后端以同样的统一工具定义和结果模型使用 MCP；上层无需按 Server 增加分支，不改变供应商配置语义。

多轮 Loop、工具请求流式收集、计划提问、模式冻结、用户取消、原生 assistant 负载、历史调用配对、缓存稳定前缀和用量结算继续正确。启动发现与审批不额外发 LLM 请求或虚增 Token；发现的工具定义进入正常工具请求，工具集变化可能改变缓存前缀，不承诺缓存命中率不变。

## 5. 非功能需求

- **N1：响应性与隔离。** 信任确认后并发启动，各 Server 独立失败；发现和调用均有期限，不能因单个异常持续卡住启动、界面或退出。运行中界面保持可响应。
- **N2：真实的安全边界。** 不自动信任只读提示；启动许可与调用许可分离。外部 Server 是独立程序/服务，获得启动信任不意味着受内置文件围栏约束，也不证明不会联网、修改文件或泄漏信息。
- **N3：凭据保护。** 示例以环境变量引用秘密；不将展开值写回配置、信任记录、规则或对话。脱敏覆盖配置失败、HTTP 错误、Server stderr、工具预览、UI 与最终回灌；不把摘要比较当作加密存储的替代。
- **N4：结果与输入规模受控。** 配置大小、Server/工具数量、工具元信息、Schema 复杂度、分页和返回内容均有合理上限，具体阈值在 Plan 明确；超限告警/结构化错误或截断，不悄悄撑爆请求与界面。
- **N5：一致性。** 请求乱序、取消、重复事件和关闭竞态不产生重复调用、错配结果、未配对历史或旧审批释放新任务。未知执行结果不自动重试副作用。
- **N6：可验证性。** 提供离线替身以及本地最小 stdio/HTTP Server 验证，覆盖真实协议传输与进程退出，不用工具适配单测冒充实际连接。真实 PowerShell 与真实模型场景分开记录；收费/外部连接另行确认。
- **N7：兼容性。** 保持现有项目最低 Python 版本与三后端能力；SDK 版本、依赖变更和兼容协议必须显式记录，不照搬参考中的 Python 3.12+ 或无限制依赖版本。若无法兼容需重新提出审批。
- **N8：范围控制。** 本阶段只允许有依据地扩展工具/权限/入口/界面等必要接入点，不要求不可能的“零修改”，也不重写原业务、LLM 流式协议或全部权限系统。

## 6. 不做的事与已接受限制

- MCP resources、prompts、sampling、roots、elicitation 等非工具能力；不自动执行 Server 发起的文件、模型调用或用户交互请求。
- Server instructions 注入系统提示、MCP 工具描述驱动权限升级、自动采用 Server 自报信任。
- 健康检查、周期 ping、自动重连、退避、自动重试副作用、运行中增删 Server、配置热加载与工具列表动态更新。
- 旧式独立 HTTP+SSE 传输、WebSocket 或任意自定义传输；不主动提供独立通知订阅能力，但保留正常调用响应所需的 SSE 支持。
- OAuth 交互式登录、自动获取/刷新 Token；本章仅静态 headers 配合环境变量引用。
- MCP 级参数/资源路径权限 DSL、可信只读工具白名单、Plan 中 MCP 调用、MCP 工具安全并发优化。
- Server 程序的操作系统沙箱、网络请求限制、远端资源配额、审计日志、二进制签名校验和包供应链认证。项目启动信任只覆盖用户确认的配置，不认证后续可执行文件或远程服务内容未变化。
- 自动下载/安装或升级 Server；生产示例不默认执行包管理器安装指令。
- 图像、音频、资源获取/解引用等多模态结果处理；不打开远端结果中的资源链接。
- 第三个 MCP 配置层、信任管理 UI、调用超时可配置化或自动跨服务故障转移。
- 以普通文件目录规则约束 MCP Server 内部操作；参数中包含项目外路径也不代表客户端已获得对远端实际访问的检查能力。
- 自动迁移用户真实凭据、权限文件或信任数据；自动调用付费模型、外部生产 Server 或推送 GitHub。

用户级 Server 自动启动，以及用户信任项目级 Server，均可能运行与当前用户具有相近权限的本地代码，或向远端发送配置的认证信息。工具默认审批不能消除启动期风险；BYPASS 和宽泛 MCP allow 规则还会扩大后续调用权限。这些限制必须出现在用户说明中，不包装成“五层防御覆盖外部 Server 的全部行为”。

## 7. 验收标准

| ID | 可观察行为与验证方式 | 对应需求 |
|---|---|---|
| AC01 | 临时用户/项目两层配置合并正确；同名完整覆盖，不从低层拼出缺失字段；缺失/空文件不触发连接。 | F1 |
| AC02 | 坏文件跳过并告警；坏单个 Server 不影响其余；项目同名定义无效或变量缺失时不回退启动用户同名定义；整文件被跳过的降级行为明确。 | F1、N3 |
| AC03 | stdio/HTTP 必填和字段类型正反例通过；env/headers 嵌入引用正确展开；未定义变量只跳过对应 Server，其他字段不展开，配置原字节不变。 | F2 |
| AC04 | 未信任的项目 Server 连接前有真实确认；拒绝/无交互时观察不到该子进程启动或该端点收到请求，其他连接与聊天仍可用。 | F3 |

| AC06 | 模型/文件/工具中的伪信任、旧确认、取消与非法选择不能启动 Server；信任保存失败/未知时提示与实际启动行为一致，不虚报记住。 | F3、N5 |

| AC13 | 精确与 Server 通配 allow/deny 按既有层序及同层 deny 优先生效；BYPASS 尊重命中 deny，且不能跳过启动信任；内置危险命令/外部路径仍按原门禁拒绝。 | F7、N2 |
| AC14 | 四种审批选择均实际覆盖；本次不记住，会话/永久只授权精确 MCP 工具身份，重启复用符合范围；界面明确后续不同参数也可能获准，永久保存不扩大为 Server 通配规则。 | F7 |
