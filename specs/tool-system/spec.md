# weizhCode 工具系统 Spec

> 状态：需求已逐段确认，本文已获用户明确批准。
> 本文定义本阶段的行为与验收边界，不代表功能已经实现或验收通过。

## 背景

weizhCode 已具备 Anthropic、OpenAI 和通义千问三种后端的流式、多轮终端对话能力，并采用轻量的 Claude Code 风格界面。目前模型只能输出文字，不能读取或修改文件、执行命令或搜索代码。

本阶段引入工具系统：模型根据用户请求选择工具，应用校验并执行，将结果回传给模型，再由模型生成一次最终文字答复。该流程只完成单工具闭环，不进入自动循环。

本阶段以此前逐段确认的需求为准。相较参考材料，明确采用“每轮最多一个工具”“修改与命令逐次审批”“现有三个后端全部适配”的范围。

## 目标

- 提供统一工具抽象和注册中心，内置读文件、写文件、改文件、执行命令、按模式找文件、搜代码内容六个工具。
- 三种后端均能完成流式工具调用解析、执行结果回灌和最终文字续答。
- 每次用户提问最多执行一个工具，随后生成一次最终答复并结束。
- 写文件、改文件及执行命令必须逐次获得用户批准。
- 在现有轻量终端界面中清晰呈现审批、执行状态、结果摘要及错误。
- 工具失败、超时或被拒绝不导致程序崩溃，用户仍可继续对话。

## 功能需求

### F1：统一工具与注册中心

- 每个工具暴露名称、面向模型的描述、参数 Schema 和执行入口。
- 注册中心集中登记六个内置工具，支持按名查找，并能导出当前后端接受的工具定义列表。
- 工具能力与执行行为不依赖具体模型协议；各后端负责协议差异。

### F2：读文件

- 读取指定文本文件，返回带原始行号的内容。
- 支持指定起始行及读取行数，默认及单次最多读取 200 行，便于后续分段读取。
- 文件不存在、不可读、属于二进制或编码不受支持时，返回明确的结构化错误。
- 直接读取指定文件不受搜索工具的忽略规则影响。

### F3：写文件

- 根据指定路径和内容创建或覆盖文本文件；父目录不存在时自动创建。
- 执行前展示目标路径及内容变更预览，获得用户批准后才允许产生写入，包括创建父目录。
- 拒绝或尚未批准时，不创建目录、不创建文件、不覆盖已有内容。
- 写入失败返回结构化错误，不把失败操作报告为成功。

### F4：改文件

- 根据指定路径、原文片段和新文片段，进行精确的唯一匹配替换，不进行模糊匹配。
- 原文恰好匹配一次时，才允许进入审批与修改流程。
- 匹配 0 次或多次时，不修改文件，返回包含实际匹配数的明确错误。
- 空原文视为参数错误；新文允许为空，用于删除唯一匹配的片段。
- 执行前展示目标路径及变更预览，获得用户批准后才修改文件。

### F5：执行命令

- Windows 使用 PowerShell，Linux/macOS 使用系统 shell。
- 默认在启动 weizhCode 的目录执行，也支持指定执行目录。
- 每次命令独立运行，不保留上一次命令产生的工作目录或环境变量变化。
- 执行前展示完整命令及执行目录，获得用户批准后才启动命令。
- 返回标准输出、标准错误和退出码；非零退出与超时以结构化结果说明，不中断会话。

### F6：按模式找文件

- 根据 glob 模式递归查找文件，支持指定搜索目录。
- 返回匹配文件的路径列表，最多返回 200 条，并遵守单次结果文本上限。
- 无匹配项属于正常空结果，不标记为执行失败。

### F7：搜代码内容

- 在指定范围内递归检索文件内容，默认按普通文本匹配，可显式启用正则表达式。
- 返回文件路径、行号及命中内容，最多返回 100 条，并遵守单次结果文本上限。
- 非法正则返回结构化错误；无匹配项属于正常空结果。

### F8：搜索范围与忽略规则

- 找文件与搜内容默认从启动目录搜索，遵循 `.gitignore`，跳过隐藏文件和隐藏目录。
- 允许通过工具参数指定其他路径，并显式包含被忽略项或隐藏项。
- 搜索路径不存在、无权限等执行问题与正常空结果明确区分。

### F9：工具定义与模型使用约定

- 对话的初次模型请求携带六个工具的定义，使模型能够选择工具并构造参数。
- 加入内置系统说明，描述助手角色、工具用途、审批要求及每轮只允许一个工具的限制。
- 模型未请求工具时，保持原有流式文字对话，不额外发起工具续答请求。

### F10：流式工具调用解析

- 区分正文、思考内容及工具调用，正文继续按增量展示。
- 正确拼接分片到达的工具名及 JSON 参数，组成完整调用，并保留调用与结果的对应关系。
- 必须在调用完整接收、参数成功解析且符合工具要求后，才允许进入审批或执行；不执行尚未完整接收的调用。
- 思考内容继续不展示，本阶段不新增 extended thinking 能力。
- JSON 无效、参数缺失、参数类型错误等情况均按结构化错误处理，不产生工具副作用。

### F11：单工具闭环与最终续答

- “一轮”指用户提交一次提问，到本次最终文字答复或限制提示结束。
- 模型请求一个工具时，完成校验、必要审批和执行，把工具调用及对应结果加入会话历史，再请求模型生成一次最终文字答复。
- 失败或被拒绝的结果同样交给模型进行最终文字解释，不自动重试工具。
- 模型同次请求多个工具时，全部不执行，不进行部分执行；将单工具限制作为对应结果回传，再生成一次最终答复。
- 最终续答阶段不允许执行新工具；若仍收到工具请求，则不执行，展示单轮上限提示并结束本轮。
- 最终续答仍以流式方式展示，本轮至多执行一个工具，不进入自动循环。

### F12：逐次审批

- 读文件、找文件、搜内容自动执行；写文件、改文件、执行命令必须逐次审批。
- 在对话区展示待执行操作，提供“允许本次”和“拒绝本次”，不使用阻断主界面的审批弹窗。
- 未作出批准前不执行；批准只适用于所展示的那一次操作，不提供本阶段的长期免确认授权。
- 拒绝作为可区分的结构化结果返回模型，审批选择及操作记录保留在当前对话中。

### F13：统一执行结果与错误处理

- 工具成功或失败均形成结构化结果，包含可区分的结果状态及相关内容或原因。
- 至少区分成功、未知工具、参数错误、用户拒绝、执行超时及执行失败。
- 文件问题、非法路径、无效正则、命令非零退出、替换匹配数不符等均清晰说明原因。
- 工具失败不出现未捕获异常，不导致应用崩溃；本轮结束后仍可继续提交新的问题。

### F14：三种后端一致支持

- Anthropic、OpenAI 和通义千问均支持工具定义注入、流式调用解析、调用与结果回灌、最终文字续答。
- 沿用现有后端选择方式；切换后端不需要修改工具系统代码。
- 对上层提供统一行为，协议差异不改变审批、执行次数、结果状态及界面体验。

### F15：工具行与执行状态

- 沿用现有轻量终端界面，在对话区以 `● 工具名(关键参数)` 形式展示工具调用。
- 展示待审批、执行中、成功、失败或拒绝等状态，并给出简短结果摘要。
- 摘要过长时截断并提示；界面摘要不替代回传模型的、受上限控制的实际工具结果。
- 工具行、审批选择、结果摘要及最终回复均保留在可滚动的当前对话记录中。

### F16：会话历史完整性

- 将模型的工具调用、对应执行结果及最终文字答复按当前后端需要的格式保留在会话历史中。
- 后续提问携带上述上下文，而不只是界面上的结果摘要。
- 历史只保存在当前进程内，程序退出后不要求恢复。

## 非功能需求

- N1：六个工具的单次实际执行统一限时 30 秒，等待用户审批不计入执行时间；命令超时后终止对应进程及其子进程，返回明确的超时结果。
- N2：工具执行及模型生成期间，界面保持响应，用户可以滚动并查看当前状态，不因执行过程冻结。
- N3：单次工具结果的文本内容最多保留 20,000 字符，同时遵守读文件 200 行、找文件 200 条、搜内容 100 条的上限。截断须明确标记，并保留结果状态、退出码等关键信息。
- N4：文件读写只支持 UTF-8 文本，包括带 BOM 的 UTF-8；修改已有文件时保留 BOM 及原有换行风格。二进制文件及不支持的编码返回明确错误，不尝试修改。
- N5：三种后端在审批、执行、结果回灌、错误反馈及界面呈现上保持一致体验。
- N6：应用已知的 API 密钥须在界面、错误信息及回传模型的工具结果中脱敏；不承诺自动识别所有其他敏感信息。
- N7：保持现有配置格式及无需工具的纯聊天体验，不增加工具开关、结果上限或超时配置项。
- N8：自动测试使用模拟协议响应、临时文件和受控命令，不依赖真实 API 凭证；真实 API 验证单独记录，不用模拟结果代替真实连通性结论。

## 不做的事

- 不做自动循环、自动工具重试或同批多工具执行。
- 不做完整权限系统、执行沙箱、路径白名单或路径越界防护；允许访问启动目录之外的路径，写文件、改文件和执行命令仍必须逐次审批。
- 不做“一次批准、后续免确认”的授权模式。
- 不做单独取消当前工具或当前模型回复的能力；仍允许退出整个程序。
- 不做工具调用与结果的持久化，不新增会话恢复功能。
- 不做自定义工具、运行时动态增删工具或通过配置启停工具；本阶段固定六个工具。
- 不做超时、结果上限的配置化。
- 不做工具行折叠展开或交互式详情视图，仅提供工具行及结果摘要。
- 不做图片等非文本工具结果。
- 不做非 UTF-8 编码支持、持久化 shell 会话或 extended thinking 功能扩展。
- 不把已知 API 密钥脱敏等同于通用敏感信息防护；用户仍需判断批准操作及访问目标的风险。

## 验收标准

### AC1：工具注册与请求注入（F1、F9、F14）

注册中心包含六个工具，能列出并按名查找；检查三种后端的请求，均含适配该后端的六个工具定义及内置使用约定。模型未请求工具时，仅完成一次正常流式回复，不额外续答。

### AC2：文件读取（F2）

读取已知文本文件，输出内容及原始行号正确；指定起始行和行数时返回正确片段，单次不超过 200 行。读取不存在、不可读、二进制或不支持编码的文件时，返回明确错误而非崩溃。

### AC3：文件写入与审批（F3、F12）

批准后可创建、覆盖文件并创建缺失父目录，磁盘内容符合请求；待审批及拒绝时，目标文件、原内容和父目录均不因该操作发生变化。拒绝记录及对应结果可见，并被用于最终续答。

### AC4：唯一匹配修改（F4、F12）

分别构造原文匹配 1 次、0 次、多次及原文为空的情形；仅唯一匹配且获批准时修改成功，其余情况文件不变并返回明确原因。新文为空时可删除唯一匹配的片段。

### AC5：命令执行与超时（F5、F12、N1）

在支持的操作系统上，批准命令后在默认或指定目录执行，能获取标准输出、标准错误及退出码；未批准或拒绝时不启动命令。验证不同命令间不保留目录或环境变量修改；超时命令及其子进程被终止，返回超时结果，会话仍可继续。

### AC6：文件查找与内容搜索（F6、F7、F8）

用已知目录验证 glob、普通文本和显式正则搜索，返回正确路径及命中位置；默认遵循忽略与隐藏规则，显式包含时能找到相应内容。无匹配项为正常空结果；无效路径、权限问题和非法正则为明确错误。

### AC7：流式组装与参数校验（F10、F13）

把工具名和 JSON 参数拆成多个片段，能组装出正确调用；混合正文不被误识别为参数。对未完整接收、无效 JSON、缺失参数及类型错误的调用，确认工具未执行，且错误得到清晰处理。思考内容不展示。

### AC8：完整单工具闭环与上下文（F11、F16）

通过“读取指定文件并总结”场景，观察模型请求工具、执行读取、结果回灌及流式最终总结，答复体现实际文件内容。再提交一条追问，验证后续请求包含对应工具调用、受上限控制的实际结果及最终答复；进程退出后不要求恢复。

### AC9：执行次数限制（F11）

模拟首次回复请求多个工具，确认没有任何工具被执行，限制结果回灌后进入一次最终文字续答；模拟最终续答再次请求工具，确认不执行并展示单轮上限提示。不存在自动重试或自动循环。

### AC10：错误与会话恢复（F12、F13）

分别触发用户拒绝、未知工具、参数错误、文件不存在、命令非零退出、修改匹配失败及执行超时，观察可区分的结构化结果与模型续答；之后再提交正常问题，应用仍能响应，不出现未捕获异常或崩溃。

### AC11：界面、响应性与体量控制（F15、N2、N3）

观察工具行的关键参数、审批入口、执行状态及结果摘要，操作记录可滚动回看；执行期间仍可滚动并查看状态。使用大文件、长命令输出、大量文件及搜索命中验证全部上限和截断标记，回传内容与界面摘要均不无界增长，关键状态及退出码仍被保留。

### AC12：跨后端一致性与验证证据（F14、N5、N8）

Anthropic、OpenAI、通义千问均通过同组模拟场景，包括工具定义、流式参数、审批、执行、结果回灌、续答及限制处理。真实 API 验证单独记录实际后端、场景及结果；未执行的真实验证不得标记为通过。

### AC13：文件格式、密钥与原有功能（N4、N6、N7）

修改带 BOM 的 UTF-8 及采用不同换行风格的已有文件，验证格式得到保留；二进制或不支持编码的文件未被修改。将应用已知 API 密钥置入受控工具输出和错误中，验证界面及回传结果均已脱敏。现有配置、流式纯聊天和多轮对话无回归。
