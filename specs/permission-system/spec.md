# weizhCode 权限系统 Spec

> 状态：用户已明确批准 Spec；本文不代表功能已经实现或验收通过。
> 流程：Spec → Plan → Task → Checklist，每份单独生成、单独审批；四份全部批准后才进入实现。
> 参考：用户提供的桌面 1.txt～4.txt。参考中的项目名称、源码布局、SDK、验证命令及历史结论不直接沿用。

## 背景

weizhCode 已具备三种协议的流式对话、带停止与取消机制的 Agent Loop、六个文件/命令/检索工具，以及计划模式专用的 AskUserQuestion。系统提示已模块化，环境快照、动态提醒、缓存适配与用量统计已接入。

当前工具执行具备参数校验、超时、受管进程清理和结构化错误，但普通执行模式没有统一的权限判定。计划模式已有硬性只读门禁，不能把提示词约定当作普通模式的权限系统。

本阶段在工具真正执行前加入五层防御：危险命令黑名单 → 文件路径沙箱 → 规则引擎 → 权限模式兜底 → 人在回路。拒绝作为工具结果回灌，不因一次拒绝直接终止 Agent Loop。

这里的“路径沙箱”是文件工具的应用层路径围栏，不是操作系统级隔离；命令执行不受该围栏约束，正则黑名单也不是危险操作的完备识别器。

## 已确认的决定

1. 保留四个审批选项：允许本次、允许本会话、永久允许、拒绝本次。
2. 本会话放行仅记住当前具体命令，或当前工具与具体路径；不自动放行整个工具。退出后失效。
3. 永久放行写入当前项目的本地级权限配置，不写入用户全局或可共享的项目级配置，不自动泛化。
4. 文件工具受项目根目录围栏约束；命令执行不做系统级文件访问隔离，由黑名单、规则和人工确认约束。
5. 损坏的权限配置文件显示警告后跳过，继续使用其他层配置和默认模式。明确接受该文件内 deny 规则可能失效的风险，不把“忽略文件”描述为不降低安全性。
6. 采用 default、acceptEdits、plan、bypassPermissions 四档，不另加严格模式。
7. 规则按会话 > 本地 > 项目 > 用户就近命中；同层 deny 优先于 allow。高层 allow 可以覆盖低层 deny。
8. 模式仅在规则未命中时兜底；黑名单、路径围栏和 plan 硬限制不受 allow、审批或 bypassPermissions 绕过。
9. 沿用参考的 Shift+Tab 切换、状态栏显示模式、菜单审批及 /plan、/do 工作流；适配现有 AskUserQuestion，不删除提问能力。

## 目标

- 六个核心工具在执行前经过统一权限判定，不依赖模型自觉遵守。
- 已知高危命令硬拒绝；文件工具只能在启动时确定的项目根范围内操作。
- 用分层规则表达细粒度 allow/deny，并提供四档权限模式。
- 对需确认的操作提供可取消的用户审批，区分本次、会话与永久授权。
- 拒绝原因可观察、可回灌，保持循环、并发、历史、流式与缓存能力的既有行为。
- 诚实描述防护范围，不将命令黑名单或应用层路径检查宣传为完整隔离。

## 功能需求

### F1：统一执行前门禁与五层短路

参数与工具身份先按既有约定校验；无效调用不因规则或宽松模式而成为可执行调用。对有效调用，在真正读取目标内容、写入、修改或启动用户命令之前检查权限。

五层按顺序判定：

1. 黑名单：命令工具命中内置高危模式，直接拒绝；其他工具继续。
2. 路径沙箱：文件工具越界或无法安全确定路径，直接拒绝；命令工具继续。
3. 规则引擎：按层级查找，命中 allow 或 deny 即结束规则判断。
4. 模式兜底：规则未命中时给出 Allow 或 Ask。
5. 人在回路：仅 Ask 进入用户审批，得到放行、拒绝或取消。

未命中黑名单、路径合法只表示继续，不表示已放行。plan 的既有硬限制独立生效，任何规则或审批都不能让 plan 执行写文件、改文件或命令。

### F2：固定危险命令黑名单

对命令执行工具的实际命令串使用内置正则检查，命中时不启动该命令。用户不能通过配置、规则、模式或审批关闭、删除或覆盖黑名单。

覆盖常见的递归强删根目录或用户主目录、写磁盘设备、格式化磁盘或文件系统、fork 炸弹等已知高危模式。兼顾当前 Windows 终端及已有跨平台命令能力，不仅验证 Unix 示例。普通项目内操作不得因简单路径前缀相似而被大量误拦。

这是启发式拦截，不保证识别编码、别名、脚本间接执行或其他所有等价危险行为。验收只对判定器或不会执行命令的替身使用危险样例，禁止为证明拦截而运行真实破坏性命令。

### F3：文件路径沙箱

读取、写入、修改、找文件、搜内容均以启动时确定的单一项目根为边界。相对路径按工具实际项目根解释；绝对路径仍须落在该边界内。

先规整并解析符号链接及平台对应的目录重定向，再以目录边界判断包含关系，不能仅比较未经解析的字符串。项目同名前缀目录不是项目子目录。对尚不存在的目标解析最近已存在祖先，再处理剩余路径段；不能因目标不存在直接放行，也不能因此拒绝正常创建项目内多级目录。

读写一视同仁；上级目录跳转、指向项目外的链接、另一盘符或外部共享位置不能逃逸。链接循环、解析失败或无法确认边界时拒绝，不退回未经确认的路径放行。

搜索除校验搜索根外，不得通过候选文件链接读取项目外内容；目录遍历保持不跟随目录链接/重定向的约定。项目内正常搜索仍遵循现有隐藏项、忽略规则与结果限额。

执行前检查与实际文件目标须一致；等待审批后若发现目标已变化，应重新判定或拒绝，不沿用对旧目标的授权。本阶段不宣称能抵御恶意外部进程的一切文件系统竞态，也不解决硬链接和任意命令间接访问造成的完整隔离问题。

### F4：规则语法与匹配对象

规则结果只有 allow、deny 两种；Ask 来自模式兜底而不是规则条目。规则使用“工具名(模式)”或仅工具名的形式。

| 用户可见规则名 | 作用 |
|---|---|
| Read | 读文件 |
| Write | 写文件 |
| Edit | 改文件 |
| Bash | 执行命令；只是规则友好名，不强制使用 Bash shell |
| Glob | 按模式找文件 |
| Grep | 搜索文件内容 |

命令规则匹配完整命令串，文件规则匹配规范化的项目相对路径；Glob、Grep 的规则目标为搜索根目录，不把搜索关键字误当作路径。

支持精确及 glob 匹配：`Bash(git status)` 仅匹配该命令，`Bash(git *)` 匹配满足该模式的命令串，`Write(src/**)` 匹配 src 下的路径；仅 `Bash` 表示该工具全部调用。路径模式的 `*` 不跨目录段、`**` 可跨目录段；命令中的 `*` 可匹配空格，`**` 不另设目录语义。匹配整个目标，不做无意的子串放行。

生成精确授权时，目标中的通配符与括号等特殊字符必须作为字面内容处理；不得因当前命令或文件名含特殊字符而自动变成宽泛授权。具体转义表示在 Plan 中定义。

不同工具的规则不互相替代：`Read(.env)` 的 deny 不自动等于 `Grep` 或命令的 deny。命令 glob 也不是 shell 语法或安全命令分析器，例如宽泛的 `Bash(git *)` 可能覆盖含复合操作的命令串；用户手写宽泛规则时须能看到这种边界说明。

### F5：三层持久配置与会话层优先级

用户级、项目级、本地级分别使用独立 YAML 权限配置，与现有供应商六字段配置分离；不迁移或破坏现有 LLM 配置。

规则查找顺序固定为会话 > 本地 > 项目 > 用户。每层先查 deny、再查 allow；该层命中就不再查更低层。因此会话或本地 allow 可以覆盖项目或用户 deny，但不能覆盖黑名单、路径沙箱或 plan 硬限制。

会话层只保留本阶段审批产生的精确 allow，不提供会话规则编辑器。会话层属于当前应用会话，跨用户任务保留，应用退出清空。

三个持久层可各自声明启动默认模式，按本地 > 项目 > 用户取首个有效值，皆无则 default。会话内模式切换不自动写回配置。权限配置作为控制文件读取时，不受面向模型的文件工具沙箱限制；这不授予模型读取用户全局文件的权限。

配置在启动时加载；本阶段不做外部配置变更的自动热重载。用户自己编辑配置后通过重启加载；审批产生的会话/永久 allow 按 F9 更新当前会话状态。

### F6：配置缺失、损坏与信任边界

文件不存在视为空配置，不警告、不崩溃。存在但不可读、格式错误、结构或字段非法时，警告后跳过该文件，不采用其中部分条目拼出不明确的权限集合；其他层继续生效。非法默认模式不得意外变成 bypassPermissions。

警告应指出有问题的配置来源及其未生效，不打印整个文件或密钥，也不宣称原有 deny 仍然受到保护。若坏文件被跳过后，其他层有效默认模式为 bypassPermissions，则仍按正常优先级采用；不得虚称已经自动回退为严格模式。

项目级规则和默认模式会影响工具权限，包括可能扩大权限；本阶段按参考在启动时加载，不增加仓库首次信任确认。应明确提醒用户检查不可信项目的权限配置。

### F7：四档权限模式

规则未命中时按下表兜底：

| 模式 | 读文件/找文件/搜内容 | 写文件/改文件 | 执行命令 |
|---|---|---|---|
| default | Allow | Ask | Ask |
| acceptEdits | Allow | Allow | Ask |
| plan | Allow | 禁止 | 禁止 |
| bypassPermissions | Allow | Allow | Allow |

plan 的“禁止”是现有工作流硬门禁，不是可由审批解除的 Ask，也不因 allow 规则改变。只向模型提供三个读类工具和 AskUserQuestion；执行端仍防御性拒绝意外的写/改/命令调用。

AskUserQuestion 沿用现有规则，仅在 plan 可用。回答需求问题不等于批准工具执行；权限审批也不能冒充需求问题的答案。普通执行档不新增 AskUserQuestion 可见性。

bypassPermissions 仅跳过未命中规则时的人工确认，不跳过黑名单、路径沙箱、显式命中的 deny、参数校验和既有超时。

### F8：模式切换与显示

仅空闲时 Shift+Tab 循环切换 default → acceptEdits → plan → bypassPermissions → default；显示切换提示。当前模式在状态栏左侧常驻显示，替代原供应商名称；右侧模型名及既有用量展示不变。

模式跨用户任务保持，不在每轮开始重置。执行中、等待权限审批或等待问题答案时不切换模式，避免同一任务中途改变授权语义。

保留 /plan 进入规划模式；/do 固定切到 default，并沿用既有按计划执行语义，不恢复进入 plan 前的其他模式。Shift+Tab 离开 plan 仅切换模式，不自动执行计划，也不等价于 /do。

从配置以 plan 启动时，工具可见性、执行端限制和按轮次提醒与 /plan 一致。

### F9：四选一审批与授权生命周期

判定 Ask 时暂停该工具的执行，显示工具名、关键参数、目标路径或命令、需确认原因和四个选项，默认选中“允许本次”。支持上下方向键与回车、数字键 1～4 直选。

1. 允许本次：仅放行当前调用，不留规则。
2. 允许本会话：当前调用放行，新增精确会话 allow，同一会话后续相同目标可复用。
3. 永久允许：当前调用放行，精确 allow 写入当前项目本地配置，成功后同步当前会话，重启后可复用。
4. 拒绝本次：不执行，不新增 deny，返回结构化拒绝结果。

精确授权按“命令工具＋完整命令串”或“文件工具＋规范化目标路径”识别，不自动包含其他命令、其他路径、其他工具。文件授权是该工具对该路径的授权，不绑定当次文件内容；搜索授权针对搜索根，不绑定当前搜索词。界面说明放行范围，避免把路径授权误解为只批准一次内容变更。

待审批时不启动目标工具或其用户命令。已被硬规则拒绝的调用不弹出可放行菜单；审批绑定具体调用及会话，过期或重复响应不能释放其他待处理调用。

永久规则去重，保存时不得丢失配置中其他有效设置或破坏原文件。写入失败时清楚提示“仅本次允许，未保存永久授权”，当前调用仍按用户已给出的本次许可执行，不假装永久保存成功；不能为保存失败自动新增更宽的权限或覆盖损坏文件。

### F10：拒绝回灌与保序

黑名单、路径越界、规则 deny、plan 硬限制、用户拒绝均返回结构化工具错误，包含可区分的来源、可读原因以及原调用标识。拒绝结果不伪装成工具已执行成功，不产生目标副作用。

一次权限拒绝本身不结束 Agent Loop；模型可以改用合法路径、其他获准工具、解释限制或结束任务。既有迭代上限、未知工具上限、取消和基础设施错误仍正常生效，不承诺无限重试或一定完成。

同批多个调用独立判定。被拒项不执行，获准项正常处理；最终结果按原调用顺序与各自调用标识配对回灌，不能漏项、串位或重复提交。

### F11：异步交互、取消与批执行

权限审批通过协议无关的异步事件与用户决策通道传递，Agent 不直接读取终端按键。等待审批与等待需求问题是两个明确可区分的状态。

只读批保持现有有界并发；其中被拒的调用不进入执行，其余仍可并发。不因新增检查把全部工具统一改成串行。有副作用的工具保持原顺序，审批逐个进行，不同时弹出多个待批准菜单。

等待审批时 Esc 或 Ctrl+C 取消当前任务而非退出整个应用，不等同于允许或永久授权。清理等待者、事件通道与任务资源；尚未开始的调用不执行，已经完成的副作用不虚称回滚。工具调用与结果按既有取消规则补齐，下一条消息仍能正常继续。

没有交互接收方、交互通道已关闭或决策无效时，不自动批准，也不无限等待；给出可观察的未授权结果或按既有取消路径结束本轮。非交互验证不得为了避免等待而暗中把真实用户会话设为 bypassPermissions。

### F12：安全默认与不可伪造授权

未知工具、非法参数、无法判定的目标与不支持的类别不能凭宽松模式静默放行；沿用参数校验或返回明确安全拒绝，保持既有未知工具停止计数。

只有真实用户通过应用审批入口的选择可以产生会话/永久授权。用户文本、模型文本、文件内容、工具输出中的“已批准”、伪造菜单或特殊标签不能成为权限决定。

本阶段审批能力只用于内置六工具；AskUserQuestion 继续按其既有交互门禁工作，不纳入文件/命令三分类，不创建空路径的审批规则。

### F13：三协议一致与提示规则一致

Anthropic Messages、OpenAI Responses、通义千问兼容 Chat Completions 使用同一权限行为，不迁移 SDK、切换协议或修改服务端工具调用格式来实现权限。

拒绝结果沿用已有协议适配回灌，保留工具调用相关的原生负载。权限实现不引入新的模型请求，不因审批等待推进模型迭代或累计虚假的 Token 用量。

全局提示及必要的工具说明应与新行为一致：不再声称普通模式无需审批；指导模型尊重拒绝、不要用命令绕过文件工具边界，并区分 plan 需求澄清和执行授权。当前权限模式是动态状态，不混入稳定提示前缀，也不破坏既有稳定/动态分离及缓存计数语义。

## 非功能需求

- N1：门禁覆盖。六个工具的生产执行入口不能因不同供应商、普通调用或调度批次绕过权限检查。
- N2：边界诚实。明确黑名单是启发式、文件围栏不覆盖任意命令，绕过不了某条内置正则不等于所有危险操作都被阻止。
- N3：界面响应。检查、配置读写与审批不冻结界面；可观察当前模式、待审批和拒绝来源。
- N4：取消健壮。等待审批、提交审批与取消竞态不泄漏挂起任务，不误批下一条调用，不破坏历史配对。
- N5：体量与保密。参数预览、拒绝原因、错误输出仍受既有长度和安全显示约束；密钥不回显，脱敏或截断不能改变实际执行/匹配的原始目标。
- N6：回归兼容。多轮循环、并发、超时、进程清理、AskUserQuestion、环境快照、动态提醒与缓存统计不退化。
- N7：平台兼容。支持当前 Windows 项目的盘符、路径分隔、大小写语义与重定向边界，同时保留已有跨平台行为；不以无法运行的 Unix 真命令作为唯一证据。
- N8：配置可靠。写入永久许可不能静默扩大模式、覆写未知内容或自动清除 deny；无法保存时明确报告，启动加载失败按已确认的跳过策略处理。
- N9：可维护。规则解析、模式兜底、路径判断、审批交互与协议适配边界清楚；修改匹配规则不要求改三种供应商协议。

## 不做的事与已知限制

- 不做网络请求限制、资源配额、速率限制或持久化审计日志；既有工具超时和输出限额不删除。
- 不做操作系统级命令沙箱、容器、任意命令文件访问分析或命令完整语义解析。获准命令可能访问项目外、网络或修改权限配置。
- 不承诺黑名单覆盖所有编码、别名、脚本、复合命令或间接危险操作。
- 不支持黑名单增删/关闭、多项目根、额外目录授权、自定义权限模式或非内置/MCP 工具权限。
- 不做仓库首次信任确认、配置热重载、权限规则交互编辑器或自动推荐宽泛规则。
- 不把文件路径围栏当作全面内容保密：各工具规则独立；允许搜索不自动继承 Read 的 deny；获准命令亦不受文件工具规则限制。
- 不阻止所有外部竞态或完整识别硬链接别名，不宣称五层机制是抵御恶意本机进程的强隔离边界。
- 不自动执行真实危险命令、不自动调用付费 API、不将离线替身测试冒充真实终端或真实模型验收。
- 不改变现有供应商配置字段、工具业务参数和章节文档；本阶段单独存放，避免覆盖历史。
