# weizhCode Agent Loop Spec

> 状态：背景与目标、功能需求、非功能需求与范围、验收标准均已逐段确认；完整 Spec 已获用户明确批准，进入 Plan 技术设计。
> 本文定义本章需求，不代表功能已经实现或验收通过。未完成四份文档的审批前，不进入实现。

## 背景

weizhCode 已具备流式对话、多轮历史、六个核心工具以及工具执行后的结果回传能力，但当前编排仍是单工具闭环：一个用户回合最多执行一个工具，再请求一次最终文字答复后停止。需要根据前一步结果决定下一步的任务，仍依赖用户反复催促。

本章引入 Agent Loop：模型依据任务和工具结果持续决策，应用校验、执行并回写工具结果，再进入下一轮，直到自然完成或命中停止条件。

本章参考用户提供的 Agent Loop 四份材料，以本次逐段确认的内容为准。保留现有项目的后端与工程约束，不照搬参考材料的项目名称、目录结构、SDK 或两协议假设。

## 已确认的关键决定

- 移除上一章写入、修改、执行命令前的逐次审批；普通执行模式和 `/do` 可以自动调用这些工具。
- 默认进入普通执行模式；`/plan` 切入只读计划模式，`/do` 切回全工具模式并立即启动执行，模式跨用户回合保持。
- 每个用户任务最多发起 25 次模型请求；最终文字回复也占一轮，同一回复的多个工具调用不分别计轮。
- 连续 3 轮整轮全部为未知工具时停止；某轮含任一已注册工具即重置计数，即使该已注册工具的参数校验或执行失败。计数不跨用户任务继承。
- 相邻只读调用可以并发，副作用调用逐个串行；不跨副作用调用重排工具。
- 保留现有三个后端协议、六个工具、供应商配置和工具级约束。
- 取消不保证回滚已有修改；进程管理不是执行沙箱。

## 目标

- 自动完成需要多个工具步骤的任务，取消现有一个工具和两次模型请求的编排限制。
- 对自然完成、迭代上限、取消、连续未知工具及模型流错误提供明确、可恢复的结束行为。
- 通过统一事件流提供实时正文、工具状态、迭代进度、Token 用量和停止原因，使循环与界面解耦。
- 在保留相对顺序的前提下并发执行连续只读调用，提高调查效率。
- 支持先只读调查并输出计划，再由用户通过 `/do` 启动执行。
- 保留参数校验、结构化错误、实际进程清理、文件行为、结果上限及密钥安全，不将无审批等同于无约束。

## 功能需求

### F1：自主多轮循环

每轮携带当前模式允许的工具定义和完整必要历史请求模型，同时流式收集回复。整轮成功结束后，有工具调用则执行允许的调用、回写结果并进入下一轮；没有工具调用则以模型正文作为最终回复结束任务。

一个回复可以包含多个工具调用，不再因调用数量大于一而整批拒绝，也不再丢弃第二次及后续模型回复中的工具调用。模型可依据结构化工具失败调整下一步，直到完成或命中停止条件。

ReAct 表示依据观察结果持续决策，不要求模型输出或界面展示内部思考过程。

### F2：停止条件

出现以下任一情况时停止本任务，向界面提供明确结束状态或原因，并允许后续新任务继续：

1. 自然完成：本轮无工具调用且有正常正文，正文即最终答复。若无工具且正文为空，显示空回复提示，不伪称任务完成。
2. 迭代上限：最多 25 次模型请求。第 25 轮仍有调用时，处理该轮允许的工具并回写结果后提示达到上限，不发起第 26 次请求或额外总结请求；该轮若已自然完成，则正常结束。
3. 用户取消：停止后续迭代和尚未开始的工具，按 F6、F7 收尾。
4. 连续未知工具：连续 3 轮的全部调用均未注册时，保留该轮对应错误结果后提示停止。含已注册工具的轮次重置计数；单次未知工具先以结构化错误回传，允许模型纠正。
5. 模型流出错：请求错误、流中断、截断或缺失有效成功结束信号时停止，不执行本轮缓冲中的调用，不自动重发请求。

取消后不得因同时达到阈值而继续执行工具或发起总结。应用主动停止的提示必须与模型最终答复区分，不能宣称未完成任务已成功完成。

### F3：统一异步事件流

循环向外提供正文增量、工具开始与结果、Token 用量、迭代进度、系统通知、任务结束及错误事件。界面仅消费事件，不参与工具选择、执行调度或下一轮决策。

工具事件能稳定关联对应调用，允许同名工具和多个在执行的工具同时呈现。所有结束路径都能让界面恢复空闲状态，而不依赖是否曾收到正文。

### F4：流式双路收集

每次模型响应同时满足两条路径：正文增量及时交给界面；完整正文、协议必要回放内容及分片工具参数被累计，用于历史保存与循环判断。

正文、工具参数和思考信息正确区分。工具块结束或参数看似已是完整 JSON，不等同于整个响应成功结束。只有整轮成功结束后才允许参数校验后的调用进入执行；未完成、错误或截断响应中的缓冲调用不能提前执行。

完整但不合法的调用按现有结构化错误与诊断回传规则处理，不伪造调用 ID 或生成无法配对的协议结果。

### F5：保序分批执行

六个工具按实际能力分为只读与有副作用两类：读取文件、按模式找文件、搜代码内容为只读；写入、修改、命令执行为有副作用。命令一律保守视作有副作用，不根据命令文字猜测其只读性。

按模型给出的调用顺序扫描，将最长连续只读区间组成并发批；遇到副作用调用则独立串行处理。前一批结束后才开始下一批。例如“读、读、写、读”对应“前两个读并发 → 写 → 最后一个读”，不能把最后一个读提前。

批内允许不同完成顺序，但工具开始展示、结果呈现与历史回传保持原始调用顺序，结果不能串位。每个工具仍有独立超时预算；一个工具失败不丢弃其他调用的结果。

### F6：历史一致与错误恢复

每轮完整助手回复及调用，与对应工具结果有序进入历史，并由下一轮请求携带。历史保存受工具级上限控制的实际结果，而不是界面短摘要；协议要求的回放信息继续保留。

自然完成、上限、取消、未知工具停止或流错误后，不得遗留缺少对应结果的已提交调用。已经完成的结果保留；已提交但未完成或尚未执行的调用补充明确的取消或停止结果。不能把未执行写成成功，也不能对结果未确认的副作用宣称没有发生或已经回滚。

真正未成功结束的模型响应不作为完整助手调用回合提交。必要收尾信息须符合当前协议的合法历史要求，不依赖一律禁止相邻同角色消息等跨协议不成立的假设。

文件不存在、参数错误、精确替换失败、命令非零退出和工具超时等普通工具错误，作为结构化结果交给模型决定下一步，不直接令应用崩溃或强制终止整个循环。后续模型流失败时，已执行工具及真实结果仍保留，不因恢复对话而悄悄重复操作。

### F7：取消当前任务与退出

模型生成、网络等待、并发批或串行工具运行期间，Esc 或 Ctrl+C 取消当前任务，停止后续迭代、关闭模型流、清理实际工具工作进程和受管命令进程，收尾后回到空闲，不退出应用。

空闲时 Ctrl+C 退出应用。保留已有整应用退出入口；应用退出也必须清理资源。取消及重复取消不能造成重复执行、挂起等待或迟到启动新的工具。

取消不是回滚；已发生的文件变化或命令副作用可能保留，界面与模型历史不能作出相反保证。

### F8：Token 用量

提取后端实际提供的每次模型请求的输入、输出 Token，用统一事件交给界面，在当前进程会话中跨迭代、跨用户任务累计。每次请求的输入包含当次重传的必要历史；累计量不是当前上下文长度，也不是直接计算出的费用金额。

同一次请求的分片、更新或重复用量报告不得被重复累加。后端未提供、取消或出错导致统计缺失时，明确标记统计不完整，不自行估算或用零冒充已知实际用量。重启后不恢复旧累计值。

### F9：进度与工具展示

运行时展示当前迭代轮次以及模型等待、工具准备和执行等可辨认状态；不能静默停在上一工具的“完成”状态而让用户无法判断是否还在续答。

支持同时展示并发工具；正文、工具行、结果摘要、停止提示与最终答复保留在可滚动回看的对话区。整轮任务防重入，运行期间允许编辑草稿，但不接受重叠任务，也不因拒绝重复提交而清空草稿。

### F10：Plan Mode 两段式

`/plan` 切入计划模式，切换本身不自动启动模型请求；后续问题可通过只读工具调查并产出计划。既限制发给模型的工具定义，也在实际执行端拒绝写入、修改或命令；不能只依赖提示词或模型自觉。

计划完成后等待用户，不自动切回执行。`/do` 切回普通全工具模式，并立即以当前对话中的计划为依据启动执行，不逐次请求批准。模式跨用户回合保持，直到再次切换；模式切换和当前模式须在界面上可辨认。

计划只保存在当前会话上下文，不另行落盘，不引入计划审批工具。计划模式仍受相同迭代上限、错误处理、取消和用量规则约束。

### F11：跨协议一致

现有 Anthropic Messages、OpenAI Responses 和千问兼容协议均支持多轮循环、完整调用与结果回传、用量、取消和计划模式。继续通过现有供应商配置选择，不因本章修改现有协议含义或删除后端。

兼容端点的能力以其实际返回为准；例如某兼容服务的真实验证不自动代表同协议的其他服务已经线上验证。

## 非功能需求

### N1：工具超时与实际清理

沿用每个工具准备与执行累计 30 秒的独立预算，不按阶段重置。并发批内各工具分别受限，不把所有工具的耗时相加作为单一工具预算。

超时、取消或应用退出须终止相应工作进程及受管命令进程，而非仅取消等待。关闭模型流、内部等待与执行资源，避免遗留挂起任务或消息通道。保留已完成结果，不将强制终止描述为副作用回滚。

### N2：界面持续响应

网络等待、流式生成、并发批和串行工具期间保持状态刷新、滚动、草稿编辑、取消及退出可用。不能让界面事件处理等待模型或工具完成而冻结交互。

### N3：结果体量受控

沿用现有上限：单次读取最多 200 行，找文件最多 200 条，搜内容最多 100 条；每份回传模型的序列化工具结果最多 20,000 字符，截断标记计入预算。界面结果摘要最多 8 行、1,000 字符，并明确提示截断。

长输出采集保持有界，命令输出持续排空，超长行或不完整检索不能被伪装成完整无匹配。界面摘要不得替代回传模型的实际受限结果。

历史不压缩、不裁剪；单结果上限与 25 轮上限不构成上下文总容量保证，多轮仍可能触及后端上下文限制。

### N4：现有文件行为不退化

保留严格 UTF-8、BOM 与换行处理、唯一精确替换、目标变化检测及临时文件归属保护。移除逐次审批不意味着放宽参数合法性、匹配唯一性或实际目标变化检查。

### N5：并发与历史安全

不同调用的参数、结果、状态及停止信息不能串位；历史统一有序提交。并发执行、失败、超时与取消相遇时，保留已经确认的实际结果，不遗漏其他调用，也不造成重复执行。任务结束后可继续新一轮对话。

### N6：密钥与安全显示

沿用已知密钥脱敏、跨正文分片保护及纯文本安全显示。密钥不出现在对话、预览、工具结果或错误输出；不打印认证头和原始异常堆栈。脱敏不能修改实际文件内容或命令参数，不承诺识别所有其他秘密。

### N7：兼容现有工程

保留现有 Python、HTTPX/SSE、六字段供应商配置、启动方式及三种协议，不因本章迁移 SDK、删减后端或新增 Ruff/mypy。技术模块、接口与文件设计在 Plan 中展开，不在本 Spec 预设参考项目的实现结构。

### N8：验证结论真实

自动测试、无界面交互测试、真实终端和真实 API 分别记录，不互相冒充。缺凭证、平台不支持、跳过或未执行的项目保持待验；参考材料中的“已验证”不作为本项目的运行证据。

## 不做的事

- 权限系统、逐次授权确认、执行沙箱及路径白名单；显式目标不被限制在项目目录内。
- 上下文压缩、历史裁剪、Token 预算限制或按用量自动停止。
- 会话、工具记录、Token 累计或计划的持久化。
- 子 Agent、任务分解工具、计划审批工具及计划自动落盘。
- 跨越写入、修改或命令调用重排只读调用。
- 多模态对话和工具结果、流式工具结果；工具结果完成后一次性回传。
- 迭代上限、连续未知工具阈值及工具超时的用户配置化。
- 本章范围之外的模型迁移、SDK 迁移、新后端协议或新增工具。

## 验收标准

- **AC1：自主多步任务** — “读取文件 → 根据内容写摘要 → 检查结果”能够跨多轮自动推进，无需用户逐步催促，不出现逐次审批。（F1）
- **AC2：自然结束与空回复** — 无工具调用的正常正文结束循环；无工具且正文为空时显示明确提示，不伪称任务完成。（F1、F2）
- **AC3：迭代上限** — 持续请求工具的受控模型最多触发 25 次模型请求；触顶后明确提示，不发第 26 次总结请求。验证第 25 轮工具结果的处理和保存符合 F2。（F2）
- **AC4：未知工具阈值** — 连续 3 轮全部为未知工具后停止；中间出现已注册工具则重置计数。未知工具返回结构化错误，不启动实际工具。（F2）
- **AC5：完整流执行门槛** — 文本实时显示，但工具只有在整轮流成功结束、调用完整后才执行；流中断、截断或错误不放行残缺调用。（F4）
- **AC6：保序分批并发** — 受控序列证明相邻只读工具确实同时执行，副作用工具等待前批完成并独立串行，结果按原调用顺序回传；同名工具也不会串位。（F5）
- **AC7：工具失败后继续调整** — 文件不存在、替换匹配失败、命令非零退出、参数错误及工具超时均产生结构化结果；模型可据此继续下一轮，不直接崩溃退出。（F1、F6）
- **AC8：停止后的历史合法** — 完成、取消、上限、未知工具停止及流错误后，已发生结果保留、已提交调用与结果完整配对；下一次提问可继续，不偷偷重做已完成操作。（F6）
- **AC9：取消与退出** — 分别在模型等待、流式输出、只读并发批和串行命令中测试取消：Esc 或 Ctrl+C 回到空闲，空闲 Ctrl+C 退出；取消后不启动后续工具，并清理受管进程。整应用退出及重复取消也无迟到执行。（F7、N1）
- **AC10：事件驱动界面** — 界面只消费统一事件即可展示文本、工具状态、进度、用量和停止原因，不自行决定下一轮或执行工具。无正文的结束路径也能恢复空闲。（F3、F9）
- **AC11：用量统计** — 多轮输入、输出 Token 正确累计并跨用户回合保留；重复报告不重复累加，缺失数据明确标记统计不完整。（F8）
- **AC12：计划模式强制只读** — `/plan` 后只提供读取、找文件、搜内容工具；即使受控模型强行请求写入、修改或命令，执行端也拒绝，磁盘与命令标记不产生副作用。（F10）
- **AC13：按计划执行** — 计划完成后等待用户；`/do` 切回全工具并立即开始执行。模式跨回合保持，普通执行模式不再逐次审批。（F10）
- **AC14：界面响应与记录** — 多轮及慢工具期间可滚动、编辑草稿和取消；重复提交不能形成重叠任务或清空未接受草稿。文本、工具行、摘要及最终回复可有序回看。（F9、N2、N5）
- **AC15：原有约束不退化** — 文件编码、换行、唯一替换、目标变化保护、结果上限、脱敏及安全显示的回归测试通过。（N3、N4、N6）
- **AC16：跨协议与证据区分** — 三种现有协议实际执行同组自动场景；真实终端及真实 API 另行验证。现有配置和启动保持兼容；缺凭证或平台不支持时保留待验，不以模拟通过代替。（F11、N7、N8）
